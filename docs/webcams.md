# 물멍 웹캠 운영·구현 안내

## 현재 화면: 물 풍경 웹캠

사용자 요청에 따라 `#livecam`과 `#livecam-test`에서 **물 관련 카메라를 무작위로** 표시합니다.
기본 선택은 물 관련 전체이며 해변·해안·항구·호수·하천으로 좁혀 볼 수 있습니다.
도시·교통·일반 풍경만 분류된 카메라와 명시적으로 공항인 카메라는 제외합니다.
항구와 교통처럼 물 분류가 함께 붙은 카메라는 유지하고 원래 분류를 표시합니다.
분류는 제공자 메타데이터이며 실제 촬영 대상이나 재생 성공의 검증은 아닙니다.

홈의 `라이브캠 물멍`은 무작위 목록에서 열 수 있는 카메라 3개를 보여줍니다.
카드를 누르면 해당 카메라의 공식 플레이어가 열립니다. 제공된 실시간 플레이어를
우선하고, 없으면 타임랩스 또는 공식 원본 페이지로 연결합니다. 실시간 제공 표시는
실제 재생 검증이 아닙니다. 홈과 전체 목록의 `다른 풍경 보기`는 순서를 다시
섞습니다. 전체 목록에서는 현재 분류를 유지한 채 1페이지로 돌아갑니다.
홈 카드와 전체 목록에는 최초 저장한 실제 사진을 `대표 이미지`로 표시합니다.
사진이 없거나 저장·읽기에 실패하면 기존 색상 배경/마스코트를 표시합니다.
대표 사진은 현재 영상이나 최신 촬영 시각을 보장하지 않으며 자동 갱신하지 않습니다.

- 저장된 목록이 없을 때만 물 관련 다섯 분류의 **첫 25개씩만** 읽고 ID 중복을 제거합니다.
  전체 국가 목록이나 후속 제공자 페이지를 순회하지 않습니다.
- 최대 125개 후보의 정규화한 목록 정보를 DB에 저장합니다. 썸네일 사진은 카메라별로
  최초 한 번 파일로 저장하고, DB에는 저장 경로·해시·크기·저장 시각·실패 상태를 기록합니다.
  영상은 저장하지 않습니다. 원본 서명 이미지 URL과 API 키도 DB에 보관하지 않습니다.
  HTTP 응답은 25개씩이며 분류, 다음/이전 탐색, 순서 섞기는 저장된 목록을 사용합니다.
  시간이 지나거나 서버를 재시작해도 자동으로 제공자 목록을 다시 받지 않습니다.
  누락 범위가 있으면 `truncated`를 표시합니다. 성공한 빈 목록도 저장합니다.
- 카메라 ID·탐색 세션의 `shuffle_seed`로 무작위 순서를 만듭니다.
  같은 세션에서 페이지를 넘기거나 분류를 바꿔도 상대 순서가 유지됩니다. 목록이 갱신돼도
  같은 카메라 목록과 seed의 순서는 유지됩니다. 순서를 다시
  섞으면 seed만 바뀌며 제공자 API를 다시 호출하지 않습니다.
- 기본 카탈로그는 현재 위치나 수집 장소와의 거리를 사용하지 않습니다.
  DB에 저장된 실제 물 풍경 카메라를 지역과 관계없이 보여줍니다.
- 공식 타임랩스·원본 페이지 링크, 제공 자료, 제공자 갱신 시각을 표시합니다.
  실제 촬영 장소와 영상 유형은 제공자의 원본 자료에서 확인할 수 있습니다.

`POST /api/data/livecams/preview` 본문 `{}` 또는 `{"page":1}`로 물 관련 전체를,
`{"page":1,"category":"coast","shuffle_seed":17}`로 해안을 조회합니다. `shuffle_seed`는
0~4294967295의 정수이며 생략하면 0입니다. 응답은 `ordering="random"`과 사용한 seed를
반환합니다. 저장 목록은 `storage="database"`, `valid_until=null`이며 `fetched_at`은
실제 목록을 가져온 시각입니다. 이 시각은 영상 촬영 시각이나 현재 재생 가능 여부가 아닙니다.
`total`은 중복·제외 처리 후 현재 분류의 목록 크기입니다. 이전 클라이언트와의
호환 필드 `matched_total`은 0, `matching_status`는 `not_requested`이며 주변 장소는 붙이지 않습니다.
React StrictMode의 동일 요청은 하나로 합칩니다. 프런트 요청 제한 시간은 최초
다섯 호출과 최초 썸네일 저장을 위해 180초이며 개별 공급자 타임아웃은 기존 설정을 유지합니다.
홈 조회 중 전체 목록으로 이동하면 서로 다른 순서의 요청도 앞선 조회가 끝난 뒤
전송하여 동시 조회 잠금과 충돌하지 않습니다. 선행 조회 실패도 다음 요청을 막지 않습니다.

최초 저장과 수동 갱신은 DB advisory lock으로 중복 실행을 막습니다. 호출 간격 2초,
기존 `WINDY_WEBCAMS_DAILY_BUDGET`(기본 30), 실패 backoff를 적용합니다.
호출 수·backoff도 DB에 저장하며 여러 프로세스와 재시작 이후에 공유합니다.
목록과 명시적인 spot_id 조회는 같은 예산을 사용합니다. 중간 호출이 실패하면 불완전한
목록을 저장하지 않습니다. 수동 갱신은 완전한 조회·검증 후 원자적으로 교체하고 이전
revision을 `superseded`로 남깁니다. 갱신 실패 또는 진행 중에도 기존 목록은 조회할 수 있습니다.

대표 이미지는 공식 이미지 호스트가 API로 반환한 작은 JPEG/PNG/WebP 주소만 사용하며,
추측한 주소·리다이렉트·API 인증 헤더를 사용하지 않습니다. 최대 8개씩 병렬로 내려받고,
파일당 512KiB 및 디코딩 크기를 제한해 실제 래스터 파일을 검증한 뒤 원자적으로 저장합니다.
이미지 실패는 카메라 목록 저장을 막지 않습니다. 카메라 ID별 성공·실패·미제공·중단 상태를
보존하므로 일반 조회와 수동 목록 갱신 모두 기존 카메라 사진을 다시 받지 않습니다.

응답의 `thumbnail_url`은 `/api/data/livecams/thumbnails/{camera_id}` 내부 경로이며,
`thumbnail_saved_at`은 보관 시각입니다. 둘 다 저장 성공 시에만 제공됩니다.
이미지 GET은 저장된 파일만 읽습니다. 파일 유실·잘못된 ID는 404이며 외부 다운로드로
대체하지 않습니다. 화면의 이미지 로딩 실패도 목록 조회나 사진 다운로드를 재시도하지 않습니다.

기존 호출자의 명시적인 `{"spot_id":7}` 주변 검색과 읽기 전용
`GET /api/data/livecams/preview/places?q=경포`는 유지합니다. 주변 검색 결과도 물 분류만
반환합니다. 장소 요청에는 목록 페이지/분류나 0이 아닌 shuffle seed를 혼합할 수 없습니다.
주변에 도시·공항 카메라만 있으면 검색을 끝내지 않고 다음 설정 반경을 확인합니다.
물 카메라를 찾거나 최대 10km까지 세 번 확인하면 끝납니다.
이 주변 검색만 기존 10분 임시 캐시와 `storage="temporary"`를 유지합니다.
이 명시적 주변 검색은 기본 물멍 카탈로그에서 사용하지 않습니다. 장소 목록 GET은
홈·오늘·지도의 해수욕장·계곡 검색에도 쓰이며 Windy 키나 외부 제공자 호출 없이 DB를 읽습니다.

## 운영자가 설정·확인할 항목

1. [Windy API 키 관리](https://api.windy.com/keys)에서 **Webcams API** 키를
   발급합니다. Point Forecast/Map Forecast용 키와 구분해야 합니다.
   [공식 Webcams 안내](https://api.windy.com/webcams/docs)는 새 키가 전 세계에
   적용되기까지 몇 분 걸릴 수 있다고 설명합니다.
2. 운영 배포 스크립트가 읽는 비공개
   `/home/cks/.config/pongdang/production.env`에 `WINDY_WEBCAMS_API_KEY`를
   설정합니다. `compose.yaml`은 이미 이 값을 backend 컨테이너에 전달합니다.
   로컬 개발 `.env`에만 입력하면 운영 서버에는 적용되지 않습니다.
   키는 `VITE_` 환경 변수나 GitHub 저장소에 넣지 않습니다.
3. 설정 변경은 기존 CI 배포 절차로 컨테이너에 반영합니다.
   [배포 스크립트](../ops/pongdang-deploy)는 정확한 환경 파일·프로젝트명 `pongdang`·
   릴리스 SHA를 지정해 Compose를 실행하고 준비 상태까지 확인합니다.
   릴리스 폴더에서 환경 파일 지정 없이 `docker compose up`을 실행하면 운영 설정을
   읽지 못할 수 있습니다. 코드 변경도 기존 CI 배포 경로를 거쳐야 합니다.
4. 배포의 initialize 서비스가 `python -m app.schema --initialize`로 목록 v12 및
   대표 사진 v15의 추가형 마이그레이션을 적용합니다. SSO 로그인 후 `/pongdang/#livecam`을 열면,
   저장된 목록을 읽고 아직 없을 때만 최초 조회·저장을 수행합니다.
   키 값 대신 HTTP 상태와 응답 `detail` 코드만 공유하면 진단할 수 있습니다.

목록을 미리 저장하거나 제공자의 변경 사항을 반영할 때는 backend에서 해당 환경의
서버 설정으로 다음 명령을 명시적으로 실행합니다. 일반 HTTP 요청에는 강제 갱신 옵션이 없습니다.

```sh
# 이미 저장된 목록은 그대로 재사용
python -m app.livecams.catalog --initialize
# 운영자가 요청한 경우에만 다시 받아 교체
python -m app.livecams.catalog --refresh
```

이 기능을 적용하기 전에 **목록만 이미 저장된 환경**은 위 `--refresh`를 한 번 실행해야
썸네일을 채웁니다. 마이그레이션과 일반 목록 조회는 이 작업을 자동 실행하지 않습니다.
이때 저장된 사진이나 이미 시도한 카메라는 유지하고, 아직 사진 시도 기록이 없는
카메라만 최초 다운로드합니다. 목록 API는 기존과 동일하게 다섯 번 호출합니다.

Compose backend의 `windy_thumbnail_data` 전용 쓰기 가능 볼륨을
`/var/lib/pongdang/windy-thumbnails`에 연결합니다. 앱 이미지 교체·재시작 후에도 유지되며
기존 읽기 전용 `attachment_data`와 DB 볼륨은 변경하지 않습니다. backend 이미지가
앱 사용자 소유로 이 경로를 준비하므로 새 볼륨도 같은 권한으로 초기화됩니다.
로컬 Python 실행은 기본 `<checkout>/.local/windy-thumbnails`를 사용하며 필요할 때만
절대 경로의 `WINDY_THUMBNAIL_ROOT`로 바꿉니다. DB와 이 파일 저장소를 함께 백업해야 합니다.

### 화면 오류와 원인

| 응답 코드 | 의미와 조치 |
| --- | --- |
| `503 WINDY_NOT_CONFIGURED` | 실행 중인 backend가 Webcams 키를 받지 못했습니다. 운영 `production.env`와 배포 시 컨테이너 설정 반영을 확인합니다. |
| `503 WEBCAM_CATALOG_UNAVAILABLE` | 목록 DB 연결 또는 스키마를 확인합니다. `app.schema --initialize`가 완료되어야 하며, DB 장애를 Windy 재조회로 대체하지 않습니다. |
| `502 WINDY_HTTP_401` | 제공자가 키 인증을 거절했습니다. Webcams 전용 키의 유효성과 신규 키 적용 시간을 확인합니다. |
| `502 WINDY_HTTP_403` | 제공자가 권한을 거절했습니다. 해당 키의 서비스 권한을 확인합니다. |
| `429 WINDY_DAILY_BUDGET` | Windy 요금제 한도와 별개인 Pongdang 자체 호출 예산입니다. 기본 30회이며 UTC 자정(한국시간 오전 9시)에 초기화됩니다. |
| `429 WINDY_HTTP_429` | Windy가 요청을 제한했습니다. 응답 `Retry-After` 이후에 다시 조회합니다. |
| `429 WINDY_BACKOFF` | 직전 실패의 재시도 대기입니다. `X-Webcam-Failure-Code`가 원인을 유지하고 화면에도 표시됩니다. |
| `429 WEBCAM_REQUEST_IN_PROGRESS` | 다른 조회가 진행 중입니다. 안내된 대기 시간 뒤에 다시 불러옵니다. |
| `502 WINDY_NETWORK_ERROR` | backend에서 공식 Windy HTTPS API로 연결하지 못했거나 제한 시간을 넘었습니다. 서버 외부 연결을 확인합니다. |
| 로그인 안내 | SSO 세션 만료·권한 거절로 API 응답 대신 로그인 페이지를 받았습니다. 다시 로그인합니다. |

최초 목록 저장과 명시적 수동 갱신은 각각 다섯 번 호출합니다. 이후 목록 탐색과 영상
링크 클릭은 퐁당 서버에서 Windy 목록 API를 다시 부르지 않습니다. 저장된 목록은 키가
없거나 자체 예산이 소진되었거나 제공자 backoff 중이어도 조회할 수 있습니다.
예산 설정 범위는 0~100이며 UTC 자정에 초기화됩니다. 최초 저장에 실패하면 빈 성공으로
표시하지 않습니다. 기존 목록이 있을 때 갱신에 실패해도 원래 조회 시각과 내용이 유지됩니다.

### 키가 있어도 영상이 없을 수 있는 경우

- 선택한 물 분류에 제공자 카메라가 없을 수 있습니다. 이때 전체 물 분류나 다른 분류를
  고를 수 있습니다. 현재 위치나 수집 장소 근처의 카메라가 없어도 전체 카탈로그를 볼 수 있습니다.
- Windy의 `player.live`가 없으면 생방송 링크가 제공되지 않은 것입니다. 타임랩스는
  생방송이 아닙니다. `status=active`와 공개 링크 존재도 실제 재생 성공을 보증하지 않습니다.
- 사진 주소는 제공자가 만료 토큰을 붙입니다. 최초 가져오기 중에 실제 파일을 보관하고
  프런트에는 퐁당 내부 이미지 주소만 전달합니다. 원본 토큰 만료는 이미 저장한 사진에
  영향을 주지 않습니다. `사진` 제공 여부와 실제 파일 저장 성공은 별개입니다.
- [무료 Webcams 요금제](https://api.windy.com/webcams/pricing)도 타임랩스 링크·임베드를
  지원합니다. 현재 목록과 타임랩스 링크를 위해 유료 요금제를 필수로 구입할 필요는 없습니다.
- 별도 `GET /api/data/livecams`는 운영자가 검토·등록한 기관 카메라 자료입니다.
  이 API가 비어 있는 것과 Windy 목록 조회는 독립적입니다. 기관 카메라를 추가할 때만
