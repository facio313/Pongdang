# 물멍 웹캠 운영·구현 안내

## 현재 화면: 물 풍경 웹캠

사용자 요청에 따라 `#livecam`과 `#livecam-test`에서 **물 관련 카메라를 무작위로** 표시합니다.
기본 선택은 물 관련 전체이며 해변·해안·항구·호수·하천으로 좁혀 볼 수 있습니다.
도시·교통·일반 풍경만 분류된 카메라와 명시적으로 공항인 카메라는 제외합니다.
항구와 교통처럼 물 분류가 함께 붙은 카메라는 유지하고 원래 분류를 표시합니다.
분류는 제공자 메타데이터이며 실제 촬영 대상이나 재생 성공의 검증은 아닙니다.

홈의 `라이브캠 물멍`은 무작위 목록에서 열 수 있는 카메라 3개를 보여줍니다.
카드를 누르면 해당 카메라의 유효한 타임랩스가 열리며, 타임랩스가 없거나 만료되면
공식 원본 페이지로 연결합니다. 홈과 전체 목록의 `다른 풍경 보기`는 순서를 다시
섞습니다. 전체 목록에서는 현재 분류를 유지한 채 1페이지로 돌아갑니다.
홈 카드의 기존 색상 배경은 실제 영상 썸네일이 아닙니다.

- 첫 요청에서 물 관련 다섯 분류의 **첫 25개씩만** 읽고 ID 중복을 제거합니다.
  전체 국가 목록이나 후속 제공자 페이지를 순회하지 않습니다.
- 최대 125개 후보를 메모리에 10분 캐시합니다. HTTP 응답은 25개씩이며 분류,
  다음/이전 탐색, 순서 섞기도 같은 캐시를 사용합니다. 누락 범위가 있으면 `truncated`를 표시합니다.
- 카메라 ID·탐색 세션의 `shuffle_seed`로 무작위 순서를 만듭니다.
  같은 세션에서 페이지를 넘기거나 분류를 바꿔도 상대 순서가 유지됩니다. 캐시가 갱신돼도
  같은 카메라 목록과 seed의 순서는 유지됩니다. 순서를 다시
  섞으면 seed만 바뀌며 캐시가 유효한 동안 제공자 API를 다시 호출하지 않습니다.
- 기본 카탈로그는 현재 위치나 수집 장소와의 거리를 사용하지 않으며 DB에도 연결하지
  않습니다. 지역과 관계없이 실제 물 풍경 카메라로 목록을 채웁니다.
- 공식 타임랩스·원본 페이지 링크, 제공 자료, 제공자 갱신 시각을 표시합니다.
  실제 촬영 장소와 영상 유형은 제공자의 원본 자료에서 확인할 수 있습니다.

`POST /api/data/livecams/preview` 본문 `{}` 또는 `{"page":1}`로 물 관련 전체를,
`{"page":1,"category":"coast","shuffle_seed":17}`로 해안을 조회합니다. `shuffle_seed`는
0~4294967295의 정수이며 생략하면 0입니다. 응답은 `ordering="random"`과 사용한 seed를
반환합니다. `total`은 중복·제외 처리 후 현재 분류의 목록 크기입니다. 이전 클라이언트와의
호환 필드 `matched_total`은 0, `matching_status`는 `not_requested`이며 주변 장소는 붙이지 않습니다.
React StrictMode의 동일 요청은 하나로 합칩니다. 프런트 요청 제한 시간은 최초
다섯 호출에 맞춰 100초이며 개별 공급자 타임아웃은 기존 설정을 유지합니다.
홈 조회 중 전체 목록으로 이동하면 서로 다른 순서의 요청도 앞선 조회가 끝난 뒤
전송하여 동시 조회 잠금과 충돌하지 않습니다. 선행 조회 실패도 다음 요청을 막지 않습니다.

동시 공급자 조회 1개, 호출 간격 2초, 기존 `WINDY_WEBCAMS_DAILY_BUDGET`(기본 30),
429 backoff를 적용합니다. 중간 호출이 실패하면 불완전한 성공 목록을 캐시하지 않습니다.
캐시·호출 수·backoff는 단일 프로세스 메모리이며 재시작 시 초기화됩니다.
호출 예산은 이 조회 프로세스에만 적용됩니다. 이 경로는 DB 쓰기·등록·지오코딩이나
웹캠 테이블을 사용하지 않습니다.

기존 호출자의 명시적인 `{"spot_id":7}` 주변 검색과 읽기 전용
`GET /api/data/livecams/preview/places?q=경포`는 유지합니다. 주변 검색 결과도 물 분류만
반환합니다. 장소 요청에는 목록 페이지/분류나 0이 아닌 shuffle seed를 혼합할 수 없습니다.
주변에 도시·공항 카메라만 있으면 검색을 끝내지 않고 다음 설정 반경을 확인합니다.
물 카메라를 찾거나 최대 10km까지 세 번 확인하면 끝납니다.
이 명시적 주변 검색은 기본 물멍 카탈로그에서 사용하지 않습니다. 장소 목록 GET은
홈·오늘·지도의 해수욕장·계곡 검색에도 쓰이며 Windy 키나 외부 제공자 호출 없이 DB를 읽습니다.

## 운영자가 설정·확인할 항목

1. [Windy API 키 관리](https://api.windy.com/keys)에서 **Webcams API** 키를
   발급합니다. Point Forecast/Map Forecast용 키와 구분해야 합니다.
   [공식 Webcams 안내](https://api.windy.com/webcams/docs)는 새 키가 전 세계에
   적용되기까지 몇 분 걸릴 수 있다고 설명합니다.
2. 운영 배포 스크립트가 읽는 비공개
   `/home/cks/.config/pongdang/production.env`에 `WINDY_WEBCAMS_API_KEY`를
   설정합니다. `compose.yaml`은 이미 이 값을 backend 컨테이너에 전달합니다.
   로컬 개발 `.env`에만 입력하면 운영 서버에는 적용되지 않습니다.
   키는 `VITE_` 환경 변수나 GitHub 저장소에 넣지 않습니다.
3. 설정 변경은 기존 CI 배포 절차로 컨테이너에 반영합니다.
   [배포 스크립트](../ops/pongdang-deploy)는 정확한 환경 파일·프로젝트명 `pongdang`·
   릴리스 SHA를 지정해 Compose를 실행하고 준비 상태까지 확인합니다.
   릴리스 폴더에서 환경 파일 지정 없이 `docker compose up`을 실행하면 운영 설정을
   읽지 못할 수 있습니다. 코드 변경도 기존 CI 배포 경로를 거쳐야 합니다.
4. SSO 로그인 후 `/pongdang/#livecam`에서 목록을 다시 불러옵니다.
   키 값 대신 HTTP 상태와 응답 `detail` 코드만 공유하면 진단할 수 있습니다.

### 화면 오류와 원인

| 응답 코드 | 의미와 조치 |
| --- | --- |
| `503 WINDY_NOT_CONFIGURED` | 실행 중인 backend가 Webcams 키를 받지 못했습니다. 운영 `production.env`와 배포 시 컨테이너 설정 반영을 확인합니다. |
| `502 WINDY_HTTP_401` | 제공자가 키 인증을 거절했습니다. Webcams 전용 키의 유효성과 신규 키 적용 시간을 확인합니다. |
| `502 WINDY_HTTP_403` | 제공자가 권한을 거절했습니다. 해당 키의 서비스 권한을 확인합니다. |
| `429 WINDY_DAILY_BUDGET` | Windy 요금제 한도와 별개인 Pongdang 자체 호출 예산입니다. 기본 30회이며 UTC 자정(한국시간 오전 9시)에 초기화됩니다. |
| `429 WINDY_HTTP_429` | Windy가 요청을 제한했습니다. 응답 `Retry-After` 이후에 다시 조회합니다. |
| `429 WINDY_BACKOFF` | 직전 실패의 재시도 대기입니다. `X-Webcam-Failure-Code`가 원인을 유지하고 화면에도 표시됩니다. |
| `429 WEBCAM_REQUEST_IN_PROGRESS` | 다른 조회가 진행 중입니다. 안내된 대기 시간 뒤에 다시 불러옵니다. |
| `502 WINDY_NETWORK_ERROR` | backend에서 공식 Windy HTTPS API로 연결하지 못했거나 제한 시간을 넘었습니다. 서버 외부 연결을 확인합니다. |
| 로그인 안내 | SSO 세션 만료·권한 거절로 API 응답 대신 로그인 페이지를 받았습니다. 다시 로그인합니다. |

물 전체 목록의 새 조회는 다섯 번 호출합니다. 기본 예산으로는 하루 최대 여섯 번
갱신할 수 있고, 각 목록은 10분 동안만 유효합니다. 홈 화면의 웹캠 영역도 같은
목록을 요청하며 캐시를 공유합니다. 따라서 여러 사용자가 하루 종일 이용하는 환경에서는
`WINDY_WEBCAMS_DAILY_BUDGET`을 제공자 허용량과 함께 검토해야 합니다. 현재 설정 범위는
0~100이며, 자체 예산 도달을 API 키 오류나 빈 카메라 목록으로 해석하면 안 됩니다.
실패 중에는 만료 목록의 유효기간을 연장하거나 이전 성공으로 대체하지 않습니다.

### 키가 있어도 영상이 없을 수 있는 경우

- 선택한 물 분류에 제공자 카메라가 없을 수 있습니다. 이때 전체 물 분류나 다른 분류를
  고를 수 있습니다. 현재 위치나 수집 장소 근처의 카메라가 없어도 전체 카탈로그를 볼 수 있습니다.
- Windy의 `player.live`가 없으면 생방송 링크가 제공되지 않은 것입니다. 타임랩스는
  생방송이 아닙니다. `status=active`와 공개 링크 존재도 실제 재생 성공을 보증하지 않습니다.
- 사진 주소는 제공자가 만료 토큰을 붙입니다. 현재 구현은 원본 사진 주소를 프런트로
  전달하지 않으며 `사진`은 제공 여부만 뜻합니다. 홈의 색상 배경은 영상 썸네일이 아닙니다.
- [무료 Webcams 요금제](https://api.windy.com/webcams/pricing)도 타임랩스 링크·임베드를
  지원합니다. 현재 목록과 타임랩스 링크를 위해 유료 요금제를 필수로 구입할 필요는 없습니다.
- 별도 `GET /api/data/livecams`는 운영자가 검토·등록한 기관 카메라 자료입니다.
  이 API가 비어 있는 것과 Windy 목록 조회는 독립적입니다. 기관 카메라를 추가할 때만
  공개 HTTPS 페이지·사용 조건·장소 연결 근거와 `LIVECAM_ALLOWED_HOSTS`의 정확한 host
  설정이 필요합니다. 등록·점검 방법은 [기관 카메라 계약](implementation/backend/spatial_livecams.md)을
  참고합니다. Windy 목록에 이 등록이나 host 설정은 필요하지 않습니다.

2026-09-16 코드 진단에서는 서버 설정 전달 경로와 위 오류 구분을 확인했습니다.
운영 SSH 연결 거절과 SSO 로그인 요구로 실행 중인 운영 키 유무·운영 API 응답은
확인하지 못했습니다. 아래 로컬 키의 공식 제공자 조회와 카메라 한 개의 타임랩스 재생
확인을 운영 컨테이너의 설정이나 전체 카메라의 재생 성공 증거로 사용하지 않습니다.

### 로컬 실행

루트 `.env`의 키를 사용하는 예시입니다. 기존 8000/5173 서버와 별도로 실행합니다.

```sh
# 저장소 루트, Python 3.14 가상환경
PYTHONPATH=backend backend/.venv/bin/python -m uvicorn app.main:create_app \
  --factory --host 127.0.0.1 --port 8001

# 다른 터미널, Node.js 24
cd frontend
APP_API_TARGET=http://127.0.0.1:8001 npm run dev -- --port 5174
```

`http://127.0.0.1:5174/#livecam`을 열면 목록이 바로 나옵니다.
`APP_API_TARGET`은 개발 서버의 백엔드 주소이며 프런트 키가 아닙니다.
production 빌드의 `/pongdang/` base, 기존 SSO gate와 Compose 구성은 유지합니다.
