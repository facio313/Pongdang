## 실제 적용과 조회

- 로컬 기존 LaunchAgent를 현재 코드 릴리스 `c41a1bfd20003c92`로 교체했다. 실행 프로세스와 최근 heartbeat, 기존 작업을 포함한 45개 작업의 DB 등록을 확인했다.
- 각 작업의 다음 실행시각이 DB에 남아 재시작 후에도 주기를 유지한다. 인증키는 기존 서버측 설정을 사용했다.
- `app.schema --initialize`로 기존 v3를 v6으로 이전했다. 기존 수집 자료는 유지하고 제공처 카탈로그 시각 등 nullable 열과 기존 기능 테이블을 추가했다.
- `/api/data`에서 신규 제공처별로 최대100행 페이지를 조회했다. 14종의 저장된 자료와 자동수질 0건, 승인 대기 상태를 확인했다.
- 프론트의 데이터 조회 → API 갱신 작업에서 45개 작업을 확인했다. ROMS 수집 완료·오류 없음·다음 실행시각을 실제 화면에서 확인했다.
- 프론트에 새 작업·제공처·지표의 한글 이름과 승인 대기 원인을 연결했다. 원본 코드도 함께 표시한다.

## 처리한 연결 문제

- 대기질 첫 호출의 HTTP 504는 재시도에서 정상 수신했다. 실패한 호출은 성공 기록이나 관측값을 만들지 않았다.
- ROMS는 긴 소수점/6자리 경계값 요청에 코드10을 반환했다. 공식 예시와 실제 성공 응답에 맞춰 안쪽으로 정규화한 5자리 경계를 사용하자 1,602개 예측이 수신됐다. 이를 모든 요청에 적용되는 공식 자릿수 제한이라고 단정하지 않는다.
- 카탈로그 등록·수정 및 예보구역 적용기간은 원천 날짜를 그대로 저장한다. 없는 발표시각을 가져온 시각으로 대신하지 않는다.
- 페이지 합계 모순·방문자 수의 비정상 문자열 등은 성공 저장을 막도록 검증했다.

## 검증과 남은 조건

- 백엔드 전체 653개 통과, Ruff 검사·100개 파일 포맷 통과.
- 프론트 전체 36개 통과, lint 및 `/pongdang/` 경로 빌드 통과.
- DB 테스트는 별도 `pongdang_test`에서만 수행했다. 운영용 로컬 `pongdang`에는 공식 API 실수집만 수행했다.
- 자동수질은 인천강화·전날 범위에서 아직 관측값이 없다. 다음 정기 수집을 실행하도록 연결했고 성공·안전 값으로 대체하지 않는다.
- 번체 관광정보는 승인 확인 뒤 활성화 가능하다. 수문 방류정보는 심의 승인 뒤 실제 응답의 시각·영향구역을 확인하여 어댑터를 완성해야 한다.
- 서울 대기질/천문/UV, 백령도 예보구역, 인천강화 수질, 군산항 HF, 비진도 조류가 경포를 대표한다고 처리하지 않는다. 방문통계는 60일 전 하루의 행정구역 통계이며 실시간 해변 혼잡도가 아니다.
- 기존 활동별 사용자 조건 합산 점수에 새 자료를 임의 가중치로 넣지 않았다. 과학적 적합성·안전 점수는 검증되지 않은 상태를 유지한다.
