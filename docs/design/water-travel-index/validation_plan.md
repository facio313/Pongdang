# 물 여행 모델과 API 검증 계획

작성일: 2026-09-14 KST. 상태: **설계 명세, 미실행**. 이 문서는 제품 코드·테스트 코드를 작성하거나 실행한 결과가 아니다. API 호출, DB 접속, 자료 수집, 모델 학습, 사용자 실험을 이번 단계에서 수행하지 않았다. 기존 로컬 변경을 그대로 둔다.

판정 상태와 필드의 정의는 `water-assessment.v1-draft` [canonical_contract.md](canonical_contract.md)를 따른다. 현재 기본 모델은 `unimplemented`, `score=null`이고, 공개 클라이언트가 실험 모델을 활성화할 수 없다. 이 계획의 `V-` 식별자는 향후 검증 사례의 식별자이며 API 필드가 아니다. 수치 합격선은 아직 정하지 않은 검증 파라미터로 등록한다. 상태 전이·자료 의미에 대한 필수 불변조건과 경험적으로 보정해야 하는 성능 목표를 구분한다.

연구의 [근거 종합](../../research/water-travel-index/synthesis.md), [주장 단위 근거표](../../research/water-travel-index/evidence_matrix.csv), [legacy 감사](../../research/water-travel-index/legacy_audit.md)를 읽고 작성했다. 아래 `HC`, `SW`, `AC`, `KR` 식별자는 근거표에서 원문으로 추적한다. 이 계획의 평가 방법과 출시 조건은 연구자가 보고한 검증 결과가 아니라 **Pongdang의 설계 제안**이다.

검토한 작업 트리는 [source_baseline.json](source_baseline.json)에 기록된 `feature/api`, `d07cd23279808e74c1998d849c240a48e06d06d2`와 당시 미커밋 변경을 포함한다. 다음 파일을 텍스트로 확인했으며 테스트 통과를 재확인했다고 주장하지 않는다.

## 2. 무엇을 검증했다고 말할 것인가

| 트랙 | 질문·분모 | 가능한 결론 | 그 결과로 주장할 수 없는 것 |
|---|---|---|---|
| S: 명세 준수 | 고정 입력과 명세상 기대 결과가 일치하는가? | 자료 의미, 상태 전이, 수식 재현, API 직렬화가 명세에 맞는다. | 점수·선호·안전이 현실에서 타당하다. |
| A: 쾌적·만족 | 특정 활동/노출 상태의 응답자가 평가한 열감각, 열적 쾌적성, 만족 각각 | 지정한 결과의 한국 표본 외부 예측 성능 | 쾌적하므로 안전하거나 참여한다. |
| B1: 진술 선호 | 명시한 선택지와 조건을 본 사람이 답한 의향/선택 | 그 질문·선택집합에 대한 응답 예측 | 실제 방문/입수 증가 또는 인과효과 |
| B2: 관측 행동 | 실제 접근 가능했던 장소·시간·활동 중 관측된 선택/참여 | 명시한 행동과 분모의 예측 | 방문자 수가 곧 수영 참여자 수, 클릭이 곧 만족 |
| C: 운영·위험 정보 | 관할·장소·시간에 맞는 운영 통제/위험 사건의 판정·전달 | 확인한 위험정보·통제의 정확한 적용과 누락/지연 수준 | 모든 위험의 부재, 개인 익수·감염 확률, 절대 안전 |

열감각·열적 쾌적성·전반 만족을 하나의 A 라벨로 평균하지 않는다. B2도 페이지 클릭, 목적지 방문, 활동 시작, 입수 시간, 실제 서핑 세션을 별도 이름·분모로 기록한다. 관측 행동의 예측 향상을 추천의 인과효과로 표현하지 않는다. 추천 효과 자체를 평가하려면 후속의 별도 개입 연구가 필요하며, 운영 통제를 무시하는 대조군은 만들지 않는다. HC02–HC09, HC18, SW01–SW06, AC01–AC04, AC12–AC15, KR01.

## 3. 명세 준수 검증 사례

아래 사례는 구현 전 검토표다. 실제 명세에서 정한 상태, 이유 코드, 적용 범위, 수치 없음의 표현을 함께 검사한다. 점수 한 값만 비교해 이유·출처·자료 유효성 오류를 놓치지 않는다. 필수 사례의 기대 결과가 틀리면 명세 준수 게이트 실패다. 이는 경험적 안전 성능 100%라는 뜻이 아니다.

### 3.1 장소·활동 지원과 안전 판단의 공백

| 사례 | 입력의 차이 | 필수 기대 결과 |
|---|---|---|
| V-S01 | 존재하는 장소, 확인한 활동 지원 근거 있음/없음/명시적 미지원 | 실제 지원 근거가 있을 때만 해당 활동 모델의 평가 대상으로 진입한다. 장소 유형·검색 키워드만으로 지원을 생성하지 않는다. 미확인과 미지원을 구분한다. |
| V-S02 | 일반 풀/워터파크를 onsen 요청, 호수·저수지를 rafting 요청 | 유형 이름만으로 온천/운항 구간 지원을 확정하지 않는다. 시설·구간·활동의 명시적 계약이 필요하다. |
| V-S03 | 공식 활동 제품에 없는 장소, 이름만 비슷하거나 먼 관측소 | 공간 연결의 승인 범위 밖 자료를 근처라는 이유만으로 해당 장소 근거로 사용하지 않는다. 공급 범위 밖은 낮은 위험이 아니다. |
| V-S04 | 안전 검사 목록이 비었거나 검사기가 설정되지 않음 | 빈 목록에 대한 `all(...)`이 참이어도 `no_known_restriction`을 만들지 않는다. 승인된 비어 있지 않은 필수 확인목록의 정의·실제 자료 충족을 검사한다. 목록 미확정이면 required_total/required_usable 등 관련 개수는 null이며 임의0이 아니다. 명시0 또는 목록 미승인에서 `data_quality.status=sufficient`를 금지한다. by_layer.support/safety/environment에도 같은 조건을 적용한다. |
| V-S05 | 실행된 검사는 일부뿐, 나머지는 미지원/결측 | 검사 완료 수와 확인하지 못한 필수 위험을 남긴다. 완료한 검사 중 block이 없다는 사실만으로 전체 안전을 승인하지 않는다. |
| V-S06 | support=supported에서 적용 중인 공식 block + 가장 좋은 기상·쾌적 입력 | safety.status=restricted를 유지한다. 평균, 낮은 가중치, 재정규화, 추천 순위로 상쇄하지 않는다. 동시에 존재하는 결측·불확실 이유도 보존한다. support=unknown의 독립 장소 경고 표시는 활동 안전 평가와 구분한다. |
| V-S07 | 경보 API 빈 응답, 과거 bulletin, ended, 현재 active 각각 | 미수신/공백·발표 이력·종료·현재 효력을 구분한다. 해제 기록 하나로 다른 위험까지 해제하지 않는다. 현재 시각의 active 상태를 제목 문자열만으로 확정하지 않는다. |
| V-S08 | 날짜/관할/장소가 다른 통제, 명시적으로 끝난 통제, 시각 미상 통제 | 범위가 맞지 않는 자료를 현재 block 또는 안전 승인으로 사용하지 않는다. 출처와 최신 적용 가능성의 미확인은 별도 이유로 남긴다. |

근거: 연구 후보 여섯 활동은 실제 장소 지원 목록이 아니다. SW08–SW11, AC08–AC11 및 legacy L-12, L-14, L-16–L-20. 공식 통제 기준과 기관 제품의 등급은 각각 원래 의미로 검증한다.

### 3.2 필수·선택 입력, 노후·충돌·재현성

| 사례 | 입력의 차이 | 필수 기대 결과 |
|---|---|---|
| V-D01 | 해당 활동/결과의 필수 입력 하나가 missing/stale/conflict/단위 미상/범위 밖 | 그 입력이 필요한 수치 결과는 계산하지 않는다. 다른 결과와 결손 이유를 구별한다. supported 활동에서 확인된 금지가 동시에 있으면 restricted가 유지되며, 지원 미확인/미지원에서 멈췄다면 safety는 not_assessed다. 결손 하나가 이 우선순위를 덮어쓰지 않는다. |
| V-D02 | 선택 입력만 결측 | 채택한 모델 명세에 정의된 선택 입력 처리만 허용한다. 명세에 없는 0·평균 대입, 선택 입력 누락에 따른 필수 입력 가중치 재분배, 높은 신뢰도 생성은 하지 않는다. 별도 축/모델 변형이면 식별자도 구분한다. |
| V-D03 | 모든 입력 없음, 메타데이터만 있음, 수집 성공이나 readings 없음 | 결과를 unknown/계산 불가로 남기며 기본 점수·추천·안전·합성 관측을 생성하지 않는다. 카탈로그 작업 성공을 현장 관측 성공으로 바꾸지 않는다. |
| V-D04 | 같은 자료를 나중에 다시 가져옴 | 기존 관측·발표·만료 시각은 그대로이며 늦은 fetch만으로 효력을 연장하지 않는다. |
| V-D05 | 하나의 원본 ID가 수정됨, 과거 revision이 다시 옴 | 수정 이력을 보존하고 평가의 as_of 시점에서 사용 가능한 버전을 선택한다. 현재 superseded라는 이유만으로 당시 알려진 값을 소거하지 않는다. |
| V-D06 | 같은 시점/범위의 제공처 값이 충돌하거나 입력 순서를 변경 | 명세의 출처 선택·충돌 정책에 따라 결정하며 입력 순서가 결과를 결정하지 않는다. 평균으로 충돌을 지우지 않는다. |
| V-D07 | 관측소/층/기준면/수심·장소 연결 미상 | 대응 관계를 임의 보완하지 않는다. 해수 수온을 욕조 수온으로, 수위를 다른 기준면의 유량으로 대체하지 않는다. |
| V-D08 | 원등급 문자열·등급 코드 3·수치 이안류지수 3 | 별도 타입/단위 의미로 처리한다. 원지수 3을 세 번째 위험등급으로 읽지 않는다. 제공처 순서형 등급을 임의 공통 효용점수로 바꾸지 않는다. |
| V-D09 | NaN/무한대/센티널/유효한 음수 조위/불검출 문자 | 비정상 수치와 유효한 음수·문자 결과를 구별한다. 불검출을 근거 없이 숫자0으로 대입하지 않는다. |
| V-D10 | 동일한 고정 입력·모델·파라미터·판정시각·공간 연결 버전 반복 | 수치·상태·선택 근거·이유가 재현된다. lineage, 모델/파라미터 버전, 입력 선택 기록으로 결과를 추적할 수 있다. |

입력의 required/optional 여부는 활동 × 대상 결과 × 장소·시즌·운영 정책의 명시적 계약이다. 사용자 의무 질문을 추가하여 임의로 결측률을 낮추거나, 중요한 위험변수를 optional로 옮겨 평가 가능률을 높이지 않는다. SW01–SW07, SW11–SW13, HC08, AC03–AC10; SourceBatch와 기존 수집 테스트.

### 3.3 시간·예보 범위와 미래 자료 누출

| 사례 | 입력의 차이 | 필수 기대 결과 |
|---|---|---|
| V-T01 | `as_of`보다 늦게 수집/발표된 예보·관측·통제 또는 수정본 | 당시 시스템이 알 수 없었던 자료를 회고 예측의 입력으로 사용하지 않는다. 실제 결과 라벨의 사후 확인은 입력 경로와 분리한다. |
| V-T02 | 발표 시각 unknown, 수집 시각은 알려짐 | 발표 시각을 수집/대상 시각으로 꾸미지 않는다. as_of 이전에 수집된 사실과 미상 발표시각의 정책을 구분한다. 해당 모델이 발표시각을 필수로 요구하면 계산을 보류한다. |
| V-T03 | 1시간·오전/오후·일·조석 극값 이벤트·중기 서술 예보 | 원래 유효 창과 의미를 보존한다. 반일 등급을 독립된 매시간 예측으로, 극값을 연속 관측으로, 서술을 가짜 일별 수치로 확장하지 않는다. |
| V-T04 | 요청 창이 자료 효력 창을 벗어나거나 일부만 겹침 | 전체 요청 시간에 유효한 것처럼 응답하지 않는다. 겹치는 원target interval을 자르거나 재비례하지 않고 그대로 반환하며, 요청과의 겹침/미평가 gap을 표시한다. 원target을 인접 요청·페이지에서 중복 집계하지 않는다. |

| V-T06 | 하루 중간에 하루 종료 후 확정된 일최고기온·일강수량 입력 | 종료 전 추천을 평가하는 입력으로 사용하지 않는다. 과거 관측 지수 재현과 당시 예보 기반 예측을 별도 실험으로 보고한다. |
| V-T07 | 강수확률 %, 시간당 mm, 일누적 mm, 강수 지속분, `<1mm` 범위 | 서로 대체하지 않는다. 범위의 중간/상한을 단일 관측값으로 만들지 않는다. 구간 연산이 계약에 있으면 구간 의미와 계산법을 보존한다. |
| V-T08 | 유효기간이 다른 직접 입력의 결합 | 먼저 승인된 시간 정렬·집계로 만든 모델의 직접 입력, 지원·안전·정책의 적용창을 교집합한다. 계산에 사용한 선택 요인도 포함하며, 교집합이 비면 평가하지 않는다. 하루의 모든 원시 시간별 샘플 validity를 동시에 교집합하는 검사와 다르다. 긴 예보·집계 창으로 짧은 관측/통제의 효력을 연장하지 않는다. |
| V-T09 | as_of 이전 발표·수집, 대상은 미래인 forecast와 관측으로 잘못 표시된 동일 값 | 정상 forecast의 미래 target을 미래 관측 오류로 거부하지 않는다. forecast observed_at는 target 시작이며 time_role로 명시하고, 최신성은 issue freshness 정책과 대상 창을 따로 검사한다. issued_at 미상·허용 나이 미정은 별도 unknown이다. |
| V-T10 | 동일한 과거 as_of 요청에서 불변 입력/평가 manifest 또는 동등한 시간 이력 있음/없음 | 이력으로 복원 가능한 요청만 역사 평가를 제공한다. 복원 불가이면 HTTP422와 error_code=history_not_reproducible이며 HTTP200 null 평가로 바꾸지 않는다. 입력 자체의 정상 결손이 기록된 재현 가능한 평가와 구분한다. |
| V-T11 | 일집계를 위한 원시 시간구간 coverage 충분/부족, 발표·수집 지식시점 충족/위반, 집계정책 승인/미정 | PAR_AGGREGATION_POLICY에 따라 원시 coverage·집계방법·누락·관측/예보 구성을 먼저 확인한다. 집계 입력의 대상 기간·이용 가능 시점과 원시 lineage를 보존한 다음 V-T08을 적용한다. 순차 원시 관측의 validity 교집합이 비었다는 이유만으로 적법한 일집계를 거부하지 않고, 오래된 원시값의 현재 stale 표시를 바꾸어 현재 안전 입력으로 만들지도 않는다. 정책 미정이면 HCI 집계/실행은 불가다. |
| V-T12 | 저장된 평가의 지식 cutoff보다 뒤 시각에 같은 평가를 조회하거나, 평가 레코드 없는 persisted target을 조회 | envelope.as_of는 고정된 조회/read cutoff다. 저장 평가의 row.as_of는 불변 지식 cutoff이며, nonnull이면 row.as_of≤envelope.as_of이고 둘의 일치를 강제하지 않는다. 평가 레코드 자체도 envelope cutoff까지 저장·이용 가능했어야 하며 오래된 row cutoff만으로 나중에 생성한 평가를 소급 선택하지 않는다. 평가 레코드 없는 target 결손 행은 row.as_of=null이다. 실제 사용 입력(used_by가 비어 있지 않음)이 있으면 row cutoff가 필수이며 그 입력 가용시각을 row.as_of와 비교한다. reference-only 입력(used_by=[])은 envelope cutoff를 따르되 과거 계산 입력이나 기여로 끼워 넣지 않는다. 참고 forecast만 있고 사용 입력이 없으면 최상위 mode=none이며 원입력 mode는 보존한다. queried_at·페이지 변경으로 row.as_of/evaluated_at/평가내용을 현재값으로 재포장하지 않는다. |

HC01–HC04, HC07, HC10, SW04–SW11, AC10이 시간 집계와 결과 전이를 제한한다. 실제 historical as_of 재현에는 당시의 원본 revision뿐 아니라 선택에 사용한 장소/관측소 메타데이터, 매핑, 상태·유효성 정책을 담은 불변 입력 manifest가 필요하다. 현재 superseded 표시와 최신 메타데이터만으로 과거 지식 상태를 복원할 수 있다고 가정하지 않는다. 필요한 immutable input manifest가 없으면 **historical 평가를 실행 가능한 것으로 인정하지 않으며**, 현재 상태 역산을 누출 없는 백테스트로 보고하지 않는다.

## 4. 비교 기준과 재현 실험

모든 후보는 목표 결과·활동·대상·입력 창이 같은 하위집합에서 비교한다. 평가 가능한 쉬운 사례만 남기는 선택을 막기 위해 전체 요청 분모, 모델별 abstention, 공통 평가집합과 제외 이유를 함께 보고한다. abstention을 오답0점이나 정답으로 변환하지 않는다.

| 비교 기준 | 역할과 구현 범위 | 비교할 수 없는 주장 |
|---|---|---|
| B0: 공식 정보만 제공 | 현재 관할·시각에 맞는 통제/운영정보와 원등급만 보존한다. 자체 A/B 수치를 산출하지 않는다. | A/B 예측값이 없으므로 쾌적성 RMSE 같은 수치로 억지 비교하지 않는다. C 전달 정확도·정보 범위·unknown 수준을 비교한다. |
| B1: 단순 모형 | 해당 결과의 학습자료 평균/빈도 또는 장소·활동·시즌별 기초 모형. 추가 후보는 소수의 정의된 원시 변수로 구성하고 학습자료에서만 적합한다. | 단순하다는 이유로 위험이 없거나 전국 일반화된다는 뜻은 아니다. |
| B2: 원 HCI:Beach 재현 | HC01의 일집계·Humidex·구름%·일강수량·평균풍속과 표/수식을 그대로 구현하는 독립 연구 기준. 원표 전사·집계 QA를 마치기 전에는 오프라인에서도 실행 가능한 모델로 취급하지 않는다. 이후 단위·경계 벡터를 원표에서 별도 계산해 재현 검사한다. | 일별 지수 재현은 한국 A/B 타당성 또는 시간별 추천 검증이 아니다. 정오/HCI+혼잡/시간당 강수로 계산하면 다른 후보로 이름 붙인다. |
| B3: 동결 legacy 재구현 | Multtara main `b160cf1c07cc0f299f9d83839557a1e987c47be4`와 legacy 감사 L-01–L-20의 범위를 명시해 **오프라인 독립 재구현 명세**를 만든다. 원코드 import·패키지 의존·DB·자격증명·서비스·Docker 네트워크를 사용하지 않는다. | 옛 코드와 같은 수치를 낸다는 사실은 과학적 정답의 증거가 아니다. 현재 Pongdang에서 지원하지 않는 입력을 꾸며 비교하지 않는다. |
| B4: 연구 기반 후보 | 목표 결과에 맞는 입력·상호작용·범위를 사전에 정한다. raw T+RH와 필요한 입력을 갖춘 열지수 모형은 별도 후보로 비교한다. | T/RH/체감지수·공식 종합등급의 구성요인을 중복 합쳐 좋아진 학습 적합도를 일반화 성능이라고 하지 않는다. |

legacy 비교에는 재구현한 파일/규칙의 명세 버전, 원감사 파일 해시, 재현 벡터 출처, 차이를 기록한다. 필요한 원입력/외부 공식 등급/시설/유량 모형이 없으면 해당 부분을 **재현 불가**로 남긴다. 수치 비교가 가능한 공통 부분과 전체 legacy 미재현 범위를 구분하고 “전체 legacy 대비 개선”이라고 보고하지 않는다. 알려진 의미 오류를 수정한 변형은 동결 legacy와 별도 모델 ID를 쓴다. fixture의 임계값을 사용자 근거로 추출하지 않는다.

HCI·legacy 수치를 A/B 응답에 대응시키는 별도 통계 모형이 필요하다면 그 변환도 학습자료에서만 적합하고 독립 평가한다. 서로 다른 척도의 오차를 직접 비교하거나 모든 활동의 기존 80점을 공통 선호 문항으로 삼지 않는다. HC01–HC02, HC08, HC10, HC18, AC03–AC04, legacy L-01–L-11.

## 5. 한국 현장 검증 설계

### 5.1 결과별 수집과 평가 지표

| 결과 | 현장 수집 단위·핵심 교란 | 평가 방법 후보와 아직 필요한 결정 |
|---|---|---|
| A 열감각 / 열적 쾌적성 / 전반 만족 | 동일 사람의 활동 시작 전·활동 중 가능한 시점·퇴수/종료 후 응답을 구분. 장비·젖음·활동 강도·노출시간·그늘/일사·개인/장소를 연결. | 척도별 순서형 모형의 로그손실/보정과 응답 분포, 적절한 척도의 절대오차를 사전 선택. 의미 있는 차이·수용할 오차는 `PAR_VALIDATION_A_ERROR`로 결정. 서로 다른 A 척도는 합치지 않는다. |
| B1 참여 의향 / 진술 선택 | 비참여자도 포함하며 선택하지 않음/다른 활동 옵션을 둔다. 장소 접근·가격·동행·시간·계절·장비·숙련·이용 목적을 기록. | 실제 설문 설계에 맞는 이항/다항 또는 순서형 손실·보정과 선택확률 평가. 같은 사람의 반복 선택은 독립 표본으로 세지 않음. `PAR_VALIDATION_B1_CHOICE`. |
| B2 실제 행동 | 장소 방문, 특정 활동 시작, 실제 입수/서핑/운항, 시간·세션을 각각 관측. 개장/휴장·요금·접근성·휴일·혼잡·동행·대안 활동·예보 노출을 기록. | 개인 선택에는 확률 손실/보정, 집계 인원에는 과산포/노출량을 고려한 count 오차 등 관측 단위에 맞는 지표. 클릭 성능과 별도 보고. `PAR_VALIDATION_B2_PREDICT`. |
| C 공식 통제·운영 정보 | 관할기관/운영자의 적용 장소·발효/종료·발표/확인 시각·정정 이력과 모델 출력 시각을 대조. 독립 확인이 안 된 경우 truth unknown. | 차단 누락·잘못된 차단·unknown과 전달 지연을 분리. `PAR_VALIDATION_C_RECALL`, `PAR_VALIDATION_C_LATENCY`. 통제에 대한 성능을 실제 사고 확률 검증으로 표현하지 않음. |
| C 위험 사건/수질·열부담의 별도 연구 | 실제 사건·노출 분모, 시료 채취·검사법·층/지점, 구조 기록의 누락을 별도 연구 설계로 수집. | 이안류 발생과 익수, 수질 초과와 개인 감염, 열감각과 생리 부담을 각각 평가. 희귀 사고 수가 부족하면 확률 예측/안전 보증은 보류한다. |

`PAR_VALIDATION_A_ERROR` 등은 하나의 모든 활동 공통 숫자가 아니다. 활동·결과·척도·대상에 따른 지표, 불확실성 산출, 합격선을 확정하는 관리 항목이다. 후보 지표 전부를 실행한 뒤 유리한 것만 고르지 않는다. 주지표·비교 기준·분석 순서·실패 조건을 평가셋 개봉 전에 고정한다.

### 5.2 활동·대상·장소별 표집

한국 동해/남해/서해 해변, 하천의 실제 운항 구간, 실내/노천 입욕 시설 중 **활동 지원과 연구 협조가 확인된 곳**을 표집한다. 행정 지역 수를 늘리는 것 자체보다 대상 장소·계절·강우·바람·시설·운영 조건의 대표성을 확인한다. 개장기에 좋은 날 방문한 사람만 모집한 표본은 비참여와 악조건에서의 의사결정을 대표하지 못한다. HC03–HC10, HC17, KR01.

수영·서핑은 입수/퇴수·장비·숙련·노출 길이, relax는 앉기/그늘/걷기, 갯벌은 실제 체험 경로·귀환 창, rafting은 구간·보트·운영자·상류 강우/방류, onsen은 실제 시설/욕조 수온·실내외 노출·개인 요구를 구분한다. 수온·풍속 센서의 위치/수심/높이, 조위 기준면과 관측소의 공간 대표성을 기록한다. SW01–SW03, SW06, AC01–AC11.

성인 결과는 아동·고령자·임신부 등에 자동 이전하지 않는다. 해당 대상의 공식 지침과 별도 검토·자료가 없으면 모델 적용 범위를 성인 자료의 범위로 제한한다. CDC의 50세 이상 감염 취약군을 열쾌적성 계수로 바꾸지 않는다. 소아·취약군 연구는 해당 대상의 적절한 연구·동의·현장 감독 절차가 확보된 별도 계획으로 다룬다. 위험 수온·입수 통제·뇌우에 참가자를 배정하는 실험은 하지 않는다. SW01–SW03, SW06, SW12–SW13, AC05–AC07.

### 5.3 반복측정, holdout, 표본 크기

1. 사람·가구/동행·장소·조사일/세션 식별자를 연구용으로 연결하고, 동일 표본/같은 강우 사건/인접 시간의 중복을 표시한다. 응답 수·사람 수·장소 수·관찰일 수·사건 수를 따로 보고한다.
2. 학습/보정/최종 검증을 분리한다. 사람 반복 자료를 임의 행 단위로 흩뜨리지 않고, 목표 일반화에 맞춰 새 사람·새 장소 holdout과 시간 순서상 뒤 시즌의 검증을 구분한다. 같은 폭우/이안류 사건의 이웃 시간은 동일 군집으로 취급한다.
3. 조정된 장소·시즌을 최종 검증에 다시 사용하지 않는다. 변환·결측 처리·변수 선택·가중치·하이퍼파라미터·임계값은 학습/보정 안에서만 정한다. 필요하면 내부 교차검증을 사용하되 외부 holdout을 대체하지 않는다.
4. pilot에서 응답 분산, 결과 비율, 반복측정 상관, 장소/날짜 군집 차이, 비응답·탈락, 필요한 효과/오차의 의미를 추정한다. 이를 바탕으로 주분석의 표본 크기와 검증 정밀도를 시뮬레이션/계산하고 `PAR_VALIDATION_N_SAMPLE_PLAN`에 기록한다. 임의 사람 수나 관찰행 수를 합격 기준으로 제시하지 않는다.
5. 군집을 보존한 불확실성 산출 또는 적절한 다층 모형을 사용한다. 장소가 적어 신뢰구간을 안정적으로 추정하지 못하면 그 한계를 보고한다. 전체 평균과 함께 사전에 지정한 장소·계절·성별/연령·장비·숙련 하위집단의 성능/자료량/unknown을 제시한다.

상충 근거와 적용범위의 이유: HC03–HC10, HC18, SW01–SW07, SW11, AC01–AC15, KR01. 현재 연구 문헌의 표본 수를 복사해 한국 연구의 표본 수로 결정하지 않는다.

| 분석 | 변경 범위와 보고할 결과 |
|---|---|
| 변수 중복/추가 가치 | raw T+RH 대 필요한 입력을 갖춘 열지수, 공식 지수만 대 구성변수 추가를 구분한다. 학습 적합도와 외부 성능·보정·평가 가능률의 차이를 함께 보고한다. HC08. |
| 가중치·곡선·경계 | 승인 가능한 후보 범위에서 가중치/곡선/경계를 바꾸어 결과·순위·abstention·block 변화를 본다. 공식 block은 어떤 가중치에서도 불변이어야 한다. 공통 활동 효용이 없으면 활동 간 순위 민감도는 운영 추천 근거로 사용하지 않는다. |
| 필수/선택 자료와 장애 | 실제 공급 장애/결측 패턴을 반영해 후보별 민감도를 분석한다. 중요한 필수 입력을 제거해 성능을 유리하게 만드는 모델 변경은 별도 버전·검토가 필요하다. |
| 관측·예보 오차/시차 | as_of에서 사용 가능한 예보와 사후 관측으로 계산한 결과를 별도로 보고한다. 후자의 성능을 실시간 예보 서비스 성능이라고 하지 않는다. 갱신 지연과 노후 허용 후보의 비용을 `PAR_VALIDATION_C_LATENCY`, `PAR_VALIDATION_COVERAGE`에 연결한다. |
| 공간 전이 | 같은 관측소/격자와 현장 실측의 차이, 새 해변·새 구간·새 시즌 성능을 분리한다. 한국 전체 평균으로 특정 장소 실패를 감추지 않는다. |
| 수질과 강우 | rain amount/duration/lag·지점·유출·시료를 구분한다. 해외 한 코호트의 72시간을 전국 해제 타이머로 고정하지 않는다. 계절 중앙값·과거 합격으로 현재 안전을 만들지 않는다. SW04–SW07. |
| 응답·선택 편향 | 비참여자/탈락·조사 시간/장소 편중·위험 시 관찰 불가를 보고한다. 단순 완전사례 성능과 결측/관찰 패턴에 민감한 분석을 구분한다. |

가중치 범위·유효성 허용시간·최소 개선·하위집단 허용 오차도 미검증 파라미터다. legacy `.80` confidence, `80/60/39` 추천 경계 또는 문헌의 상관/R²를 출시 합격선으로 복사하지 않는다.

| G_PARAMETER_TRACE | 모든 계수·정책·검증 파라미터 항목의 source origin/값·단위·범위·승인·버전; pilot 표본 계획과 한국 보정 기록 | 값의 출처와 적용 범위를 설명할 수 있다. 문헌 인용만으로 경험적 검증을 대체하지 않는다. |

| G_EXTERNAL_VALIDATION | 새 장소/시즌·시간 순서 holdout, 고정 모델/파라미터, 사전 검증 파라미터 기준, 불확실성/하위집단·범위 공백 | 기준을 충족한 결과·대상·장소 범위에 한정한 타당성 주장만 허용한다. |
| G_FE_RELEASE | API와 프론트 표시의 null/상태·출처·효력 창/메시지/순위 금지 및 실험 모델 공개 차단 검증 | 승인된 결과만 계약의 의미로 표시한다. 본 문서에서는 프론트 수정·테스트를 실행하지 않았다. |
| G_OPERATIONS | 실제 공급/장애/통제 지연 검증, 실패 시 unknown/중단 정책, 버전·변경 이력 | 별도 구현·운영 검토를 거쳐 승인 범위에서만 적용한다. 문서 작성 자체가 실행/배포 승인이 아니다. |

각 게이트는 pass/fail/pending/not_applicable을 사용하며 현재 작성 단계의 미실행 항목은 pending이다. 단지 미구현이거나 자료가 없다는 이유로 not_applicable 처리하지 않는다. not_applicable은 해당 모델 범위에서 적용하지 않는 이유와 승인 범위가 명시된 경우에만 사용한다. 기본 모델을 validated로 승격하려면 코드 검사와 별개로 해당 `validated_scope`의 외부검증이 필요하다.

버전은 최소 모델 정의, 입력 선택/공간 연결, 파라미터 묶음, 공식 정책 매핑, 검증 데이터/분석계획을 추적한다. 같은 평가셋을 보며 계수를 바꾸면 새 후보이며 기존 외부검증 성공을 승계하지 않는다. 운영 중 분포/공급 범위가 바뀌거나 기준을 위반하면 영향을 받는 활동·장소/대상의 주장을 보류하고, 근거 없는 이전 숫자/최신값으로 조용히 대체하지 않는다. 재보정은 새 파라미터 버전과 변경 사유·검증 범위를 남긴다.

## 8. 다음 단계의 검증 보고서 형식

보고서는 트랙별 실행 여부와 미실행 사유, 입력/라벨 출처와 hash·기간·대상·중복, 모델·파라미터·코드 버전, as_of 재현 가능 범위, 표본/관찰일/사건 분모, split/holdout과 변환 적합 범위, 기준 모델, 주지표와 불확실성, abstention·누락·노후·충돌·통제 위반, 하위집단·민감도·반례, 검증 파라미터 기준의 충족/미충족/pending를 기록한다.

소프트웨어 검사의 통과 수를 논문 근거의 강도나 한국 사용자의 만족 정확도로 제시하지 않는다. 검증에서 실패한 가정과 비교 불가 영역을 본문에 남기고, 결과를 본 뒤 바뀐 방법은 변경 기록과 다음 검증 계획으로 분리한다. 현재 이 문서의 모든 현장·통계·구현 검증은 **계획 단계**다.
