# 물 여행 적합도 지수·백엔드 API 설계 패키지

2026-09-14 KST · `water-assessment.v1-draft` · **명세 작성 완료 / 제품 미구현 / 현장 검증 미실행**

앞선 [근거 연구](../../research/water-travel-index/README.md)를 실제 Pongdang 작업 트리와 대조하여 작성했다. 이번 변경 범위는 이 문서 디렉터리다. 제품 실행 코드·프론트엔드·DB·수집기·배포와 기존 연구 파일은 변경하지 않았다. 새로운 문헌 검색이나 모델 계산을 수행한 결과가 아니다.

## 핵심 설계 결정

1. **활동 가능 장소부터 확인한다.** 여섯 활동 enum이나 해변/하천 같은 장소 분류만으로 `supported`를 만들지 않는다. 영구 미지원, 지원 미확인, 일시적인 공식 통제를 분리한다.
2. **공식 제한을 좋은 환경 점수로 상쇄하지 않는다.** 지원된 활동의 확인된 제한은 `restricted`, 필수 안전 확인 부족은 `unknown`이다. `no_known_restriction`은 승인된 비어 있지 않은 확인목록을 충족한 범위의 제한 부재이며 안전 보장이 아니다. SW08–SW13, AC08–AC10과 기존 규칙 감사에 연결한 설계 불변조건이다.
3. **현재 자체 점수와 선호 순위는 null이다.** 0–100을 도입하면 특정 모델의 규칙상 환경지수이며 만족·안전 확률이 아니다. 한국의 같은 결과 척도에서 검증하기 전 활동 간 단순 점수 정렬을 선호로 제시하지 않는다. HC01–HC02, HC18, KR01.
4. **실험과 공개 모델을 분리한다.** HCI:Beach는 일별 해변 관광 기후 지수의 오프라인 재현 후보다. 원표·열지수·집계 검수조차 미완료여서 현재 실행 가능한 모델로 취급하지 않는다. 공개 숫자는 `validated`·범위에 맞는 외부검증·적용 게이트 통과와 지원/안전/입력 충족이 모두 필요하다. 이 출시 조건 자체는 설계 정책이다.
5. **자료의 의미를 보존한다.** 수치와 표시 문자열, 관측과 예보, 집계창과 유효창, 제공처 원ID와 저장용 digest를 구분한다. 실제 target manifest 밖의 날짜를 만들지 않는다. 조회 cutoff와 불변 평가 cutoff를 구분하고, 이력이 없으면 과거 결과를 재현했다고 응답하지 않는다.
6. **후속 검증은 결과별로 설계한다.** 열감각·쾌적성·만족, 진술 선택, 실제 참여, 클릭·방문, 공식 제한 전달을 구분한다. 한국 조사·관측과 장소/시즌을 분리한 검증 전에는 미정 계수를 임의 수치로 채우지 않는다.

각 연구 ID는 [근거표](../../research/water-travel-index/evidence_matrix.csv)의 원문 확인 위치와 안정된 출처로 추적한다. API 부하 상한이나 상태 우선순위처럼 논문이 직접 정하지 않은 값은 파라미터 등록부에서 `설계가정`으로 표시했다. 값166개는 검증된 계수166개라는 뜻이 아니다.

## 프론트엔드 동료에게 전달할 범위

먼저 [연동 안내](frontend_integration.md)와 [응답 예시](api_examples.json)를 함께 전달한다. 현재 디자인·라우트·실자료 표는 유지하고, 별도 평가 DTO와 응답 검증, 기존 화면의 평가 표시 연결, null/제한/확인 필요/예보 범위 밖 구분만 후속 구현 대상으로 삼는다. 현재 서버가 제안 endpoint를 제공한다고 가정하여 연결하지 않는다.

`requestData`의 기존 `/pongdang/` base 경로를 재사용한다. `score=0`과 `score=null`을 구분하며, 추천 문구는 활동·지원·안전·평가 상태의 메시지 코드로 정한다. 예시 숫자를 기본 카드 값으로 복사하거나 공개 실험 모델을 켜는 query를 만들지 않는다.

## 변경·검수 기록

- 근거 연구와 실제 미커밋 작업 트리를 대조해 설계 초안을 작성했다. Pongdang 기준은 `feature/api @ d07cd23279808e74c1998d849c240a48e06d06d2`다. 기존 파일216개 해시는 내용을 모두 연구 대상으로 읽었다는 주장이 아니라 보존 검사용 기록이다.
- 역할을 나누어 API/프론트 계약, 파라미터, 검증 계획을 작성하고 통합 검토했다. 독립적인 학술 체계적 문헌 검토를 새로 수행한 것이 아니다.
- 통합 검토에서 공식 제한·필수 결손의 우선순위, caution과 환경 미평가의 동시 표시, 공개 후보 모델의 숫자 차단, 시간 집계와 유효창, 원본 station/provider ID 의미를 정합시켰다.
- 저장 투영의 불변 평가시각을 조회시각과 분리하고, 평가 ID가 없는 target도 안정적으로 식별하는 `target_id`를 추가했다. GET에서 평가·ID 생성을 위한 쓰기는 허용하지 않는다.
- 최종 정적 검사 결과는 [validation_report.json](validation_report.json)에 기록한다. 이 검사는 CSV/JSON·ID 연결·문서 링크·문서용 사례와 기존 파일 보존을 확인한다. 후속 구현 테스트, DB 테스트, 한국 현장 연구, 통계적 성능 평가를 실행한 것으로 해석하지 않는다.

## 남은 설계 승인·실증 과제

정식 장소별 지원 목록과 적용 안전 확인목록, 제공 자료의 허용 나이·공간 대표성, 활동별 환경 반응함수·대상 범위, 공통 선호 척도, 검증 합격선은 아직 미정이다. 각각 파라미터 ID와 후속 조사/보정 방법을 등록했다. 이 미정 상태는 이번 산출물의 누락이 아니라 근거 없이 값을 고정하지 않기 위한 명시적인 결정이다. 별도 구현 단계에서도 해당 조건을 충족하기 전에는 필요한 평가를 보류한다.
