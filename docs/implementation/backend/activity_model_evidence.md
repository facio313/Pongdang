# A1 여섯 활동의 점수 근거와 구현 경계

검토일: 2026-09-14 KST. 대상은 `swim`, `surf`, `relax`, `mudflat`, `onsen`, `rafting` 전체다. 이 문서는 기존 연구·설계·번들 파라미터를 읽고 핵심 1차 출처를 재확인한 구현 권고다. 전수 문헌 갱신, 현장 조사, 운영 DB 조사, 모델 외부 검증을 수행한 보고서는 아니다. 여기 제안한 계약의 구현 완료 여부는 실제 코드와 테스트에서 별도로 확인한다.

## 결론과 현재 확인 결과

여섯 활동을 모두 선택·조회하고 각 활동의 실제 자료, 지원 여부, 제한 상태, 계산 보류 사유를 프론트에 연결할 수 있다. 하지만 현재 자료는 한국의 여섯 활동에 공통 적용되는 검증된 환경/선호 0–100 모델을 제공하지 않는다. 사용자에게 종합 숫자를 제공하려면 **사용자가 명시한 조건에 대한 가중 일치율**을 별도 계약으로 만들거나, 실제 모델 보정·외부 검증을 완료해야 한다. 두 결과의 이름·필드·검증 상태를 구분한다.

현재 [모델 레지스트리](../../../backend/app/water_index/registry.py)의 기본 모델은 `status=unimplemented`, `validation_status=not_evaluated`, `evidence_level=insufficient`다. 여섯 활동 프로필 모두 `unapproved`이고, 필수 안전 확인 및 필수 환경 입력 집합은 `None`이다. [번들 파라미터](../../../backend/app/water_index/parameters.json)의 166개 항목은 다음과 같이 분류돼 있다. 출처 ID가 있다는 사실만으로 실행 가능한 계수가 승인됐다는 뜻은 아니다.

| 번들 상태 | 수 | 해석 |
|---|---:|---|
| `retired_or_not_adopted` | 74 | 재사용하지 않는 기존 규칙/수치 |
| `adopted_design_constraint` | 25 | 계층 분리 등 설계 제약 |
| `experimental_offline` | 4 | 오프라인 비교용 후보 |
| `unresolved` | 60 | 값이 `null`인 미정 항목 |
| `draft_operational_policy` | 3 | 적용 범위·실행 전 검수가 필요한 운영 정책 초안 |

여섯 활동의 `PAR_{ACTIVITY}_RESPONSE_FUNCTION`, `ENVIRONMENT_REQUIRED_INPUTS`, `SAFETY_REQUIRED_CHECKS`는 모두 `unresolved/null`이다. 테스트를 통과해도 이 값이 자동 승인되거나 현장 결과 검증을 대신하지 않는다. 상세 기준은 [기존 모델 명세](../../design/water-travel-index/model_spec.md), [근거 종합](../../research/water-travel-index/synthesis.md), [검증 계획](../../design/water-travel-index/validation_plan.md)을 따른다.

## 실행 가능한 별도 점수: 사용자 조건 일치율

이 제안은 문헌으로 보정된 여행 적합도 모델이 아니다. 사용자가 선언한 조건에 실제 자료가 얼마나 일치하는지 산술로 설명하는 제품 계약이다. 다기준 분석은 판단기준·척도·가중치와 그 민감성을 드러내야 하며 중복 계산을 점검해야 한다. 이는 [영국 정부 다기준 분석 매뉴얼](https://assets.publishing.service.gov.uk/media/5a790545e5274a2acd18b975/1132618.pdf)의 §§5.4.4.4–5.4.4.5 및 §6.2.14가 다루는 일반 방법론과 일치한다. 이 매뉴얼이 Pongdang의 활동별 계수나 유효성을 검증하는 것은 아니다.

### 의미와 입력

권장 이름은 **종합 조건 일치율**, 필드는 `condition_match`다. `environment.score`, `preference.score`, `safety`의 의미를 바꾸지 않는다. 조건의 최소 입력은 `condition_id`, `activity`, `input_name`, `unit`, `minimum`/`maximum`, `weight`, `profile_version`이다. 집계·공간·시간 계약은 검수된 실제 입력 레시피에 바인딩한다. 의료 정보나 계정은 새로 요구하지 않는다.

범위와 중요도에는 **제품 기본값을 넣지 않는다**. 활동을 선택했다고 이미 그 활동의 이상 수온·이상 풍속이 정해졌다고 간주하지 않는다. 사용자는 각 조건의 범위와 중요도를 입력하거나 명시적으로 동등 중요도를 선택할 수 있다. 후자의 경우도 과학적 균등 가중치가 아니라 사용자 선언이다. 사용자의 조건을 바꾸면 별도의 프로필 버전/해시를 사용한다.

### 계산 정의

각 조건의 비교 결과는 다음처럼 단순하게 정의한다. 경계는 포함한다.

```text
match_i = 1  if minimum_i <= verified_value_i <= maximum_i
          0  if a verified finite value is outside the declared range
       null  if a required value or its contract is missing/invalid

condition_match_percent = 100 × Σ(weight_i × match_i) / Σ(weight_i)
```

한쪽 경계를 생략한 조건은 명시된 쪽만 비교한다. 적어도 하나의 경계가 필요하며, 양쪽 경계가 있으면 `minimum <= maximum`이어야 한다. 가중치는 유한한 양수다. 실제 입력과 범위의 단위가 같거나 검수된 단위 변환이 있어야 한다. 100은 모든 선언 조건이 맞았다는 뜻이고, 0은 모든 조건에 실제 유효값이 있으나 하나도 맞지 않았다는 뜻이다. 만족 확률, 안전 확률, 활동의 우열, 관측 정밀도는 아니다. 조건 경계 바로 밖에서 0으로 바뀌는 것은 선언한 범위 비교의 특성이며 자연현상의 불연속을 주장하지 않는다.

### 보류 및 금지 처리

- 선택한 조건 중 하나라도 결측·노후·충돌·잘못된 단위·공간 불일치·정의 불일치가 있으면 종합은 `null`이다. 남은 조건의 가중치를 재분배하지 않는다. 각 조건의 원자료·진단·일치 상태는 계속 표시한다.
- 조건이 없거나 범위/중요도가 미입력이면 `not_configured`다. 빈 목록을 100으로 계산하지 않는다.
- 확인된 활동 미지원이면 종합 점수를 보류한다. 지원을 모르는 경우 `support_status=unknown`을 유지하고 장소 유형만으로 지원을 만들지 않는다. 단위·시간·공간 정의가 확인된 관측소 자료와 사용자 범위를 비교하는 순수 산술은 별도 조건 계약에서 허용한다. 이 경우 점수 옆에 활동 지원 미확인을 함께 표시하고 해당 장소에서 활동을 할 수 있다는 의미로 설명하지 않는다.
- 확인된 제한은 `restricted`로 유지하며 공개 종합 조건 점수를 보류한다. 미승인 필수 안전 확인목록/미확인 필수 자료가 있으면 `safety_status=unknown`을 유지한다. **환경 점수의 기존 공개 보류 정책은 그대로 적용**하고, 새 조건 계약의 산술 일치값은 안전 미확인과 함께 표시할 수 있다. 이는 안전 판정 게이트 통과가 아니라, 환경 평가와 분리한 정보용 조건 비교를 허용하는 제품 결정이다. 추천·순위·안전·활동 가능 문구로 이어지지 않도록 한다.
- 종합 점수의 보류 사유와 `safety.status`는 같은 문자열로 합치지 않는다. 모델 미검증·자료 미확인·활동 제한을 사용자가 구별할 수 있어야 한다.
- 공식 등급은 원등급으로 표시한다. `좋음`을 임의로 80점으로 바꾸거나 UV/혼잡을 추가해 문헌 모델처럼 합산하지 않는다.

### 종합의 단위

1. **한 활동 안의 종합:** 해당 활동에서 사용자가 선택한 조건의 가중 일치율이다. 같은 활동·프로필·입력 계약·시간 집계끼리 비교한다.
2. **여섯 활동을 묶은 종합:** 활동별 환경 점수의 평균은 공통 효용을 만들지 않는다. 사용자가 각 활동의 비중까지 직접 지정하더라도 결과는 그 선언 조건들의 일치율로만 설명해야 한다. 선택한 활동 중 하나라도 필요한 평가가 없으면 누락 활동을 빼고 다시 평균하지 않는다.
3. **활동 추천/순위:** 서로 다른 활동의 조건 집합·범위가 다르므로 기본값으로 자동 순위를 만들지 않는다. 실제 공동 선택 자료로 활동 간 효용을 검증하는 작업은 별도다.

## 프론트 연결과 검증 기준

여섯 활동 모두에 같은 조회·선택 계약을 적용하되 표에는 활동별로 지원 상태, 공식 제한/미확인, 환경 모델 검증 상태, 종합 조건 일치율, 평가 보류 사유를 나란히 표시한다. 숫자가 없는 행도 남긴다. 목록에서 선택한 장소·활동·대상시간·조건 프로필이 상세와 지도/예보 링크까지 유지되어야 한다. 조건을 바꾸면 이전 응답/점수를 새 조건의 결과처럼 보여 주지 않는다.

실제 입력은 서버의 승인된 collection/evaluation 경로에서 읽는다. 프론트가 임의 수온을 공급한 테스트 수치를 운영 자료로 표시하거나 retired demo 자료를 사용하는 API를 새로 만들지 않는다. 기존 제한·단위·입력 revision·관측/대상/만료 시각을 함께 표시하고 서버의 종합 산식과 프론트의 별도 재계산이 서로 어긋나지 않게 한다.

검증은 다음 세 층을 구분한다.
