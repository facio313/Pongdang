# Pongdang A1부터 순서대로 확인할 작업 목록

작성: 2026-09-14 KST. 경수(백엔드 담당자)와 기능별로 확인하기 위한 목록.
기준: [BACKEND_GOAL.md](../../../backend/BACKEND_GOAL.md), 현재 코드,
[구현 기록](README.md), [프론트 연결 설명](frontend_briefing.md).

초기 목록은 코드·문서 대조로 작성했다. 이후 사용자가 여섯 활동 모두와 활동 내 종합 점수·프론트 연결을 요청하여 후속 구현·격리 검증을 진행했다. [최신 구현·검증 결과](activity_conditions.md)를 함께 확인한다. 운영 DB와 최신 배포 상태는 재검증하지 않았다.
아래 미완료 항목은 구현 경로가 존재하는 것과 제품 기능이 완성된 것을 구분한다.
체크는 결정 내용 또는 검증 결과가 기록되었을 때 갱신한다.

경수는 첫 검증 범위·제품 목표·자료 확보 경로를 결정한다. 자료 조사, 설계 후보,
코드와 테스트는 Codex가 준비할 수 있다. 화면 구현은 프론트 담당자에게 인계한다.
외부 자료의 실제 타당성 검수에는 해당 근거와 검수 책임자가 필요하다.

B1~B5 전체 추천·대화 제품은 이번 목록에 확대하지 않는다.

## A1 — Water Index 세부 점검

현재 확보된 코드 경로:

- [x] 실제 수집자료를 평가 입력으로 변환하는 producer와 주기 작업.
- [x] 활동 지원·제한·결측 사유를 구분하는 판정기와 불변 근거 저장.
- [x] assessments / support / coverage 조회 API.
- [x] 기존 허브 결과 문구에 API 상태 연결.

위 체크는 코드 경로 확인이다. 운영 활성화 또는 수치 모델 검증 완료 표시가 아니다.
현재 모델은 `unimplemented`, 검증 상태는 `not_evaluated`이며 점수는 null이다.
후속 프론트는 사용자 장소·여섯 활동·관측/예보·시각 선택을 지원한다. 명시한 범위·중요도로 계산한 별도의 종합 조건 일치 점수를 표시하며, 과학적 환경 점수는 여전히 null이다.

- [x] **A1-1. 대상 활동 범위 선택 — 전체 여섯 활동으로 사용자 결정.**
  전체 활동 계약은 수영·서핑·휴식·갯벌·온천·래프팅을 포함한다. 이 중 먼저 검증할 활동과
  사용자는 전체 여섯 활동을 검증하고 화면에서 선택하도록 요청했다. 장소는 수집 카탈로그에서 사용자가 고른다. 실제 여행지별 대표성 검수는 A1-3에 남긴다.
- [ ] **A1-2. 지수가 설명할 결과와 공개 범위 확정 — 경수와 Codex.**
  해당 활동에서 환경 적합도가 무엇을 뜻하는지 정의한다. 쾌적성·만족·선호·안전·제한의 의미를
  섞지 않는다. 완료 근거: 평가 목표, 대상 사용자/조건, 표시할 결과와 보류 조건이 담긴 명세.
- [ ] **A1-3. 실제 장소와 관측소의 연결 근거 검수 — Codex 정리, 근거 검수 후 백엔드 등록.**
  좌표·대표 구역·대상 활동·유효기간·출처를 확인한다. 가까운 관측소라는 이유만으로 장소의
  직접 측정값처럼 쓰지 않는다. 완료 근거: 검수한 mapping과 실제 입력에서 참조되는 mapping ID.
- [ ] **A1-4. 활동 지원·운영 제한 근거와 필수 확인 항목 확정 — Codex 조사, 근거 검수 후 구현.**
  장소의 활동 지원, 공식 통제와 적용 구역/기간, 반드시 확인할 항목을 정한다.
  완료 근거: 등록된 지원/제한 자료와 누락·만료·정정 시 판정 규칙. 근거 부족은 unknown으로 남긴다.
- [ ] **A1-5. 수치 모델과 입력·파라미터 명세 확정 — Codex 설계 후보 작성, 경수 범위 선택, 검증 근거 확보.**
  필수 입력·단위·집계·신선도·공간 범위·계산식·계수·결측 처리와 근거를 정한다.
  완료 근거: 선택 활동의 미정값과 실험값을 구분한 실행 명세와 파라미터 버전.
- [ ] **A1-6. 수치 계산 구현 및 기존 평가 경로 통합 — Codex/백엔드.**
  확정한 계산을 producer·평가 저장·조회와 연결한다. 완료 근거: 입력/모델/파라미터 버전으로
  같은 결과를 재현하고, 결측·만료·충돌·정정에서 잘못된 점수를 내지 않는 자동 검사.
- [ ] **A1-7. 실제 자료로 모델 타당성 검증 — 검증 자료 확보, Codex 분석·자동화.**
  대상 결과에 맞는 실제 표본과 검증 기준을 확보한다. 소프트웨어 검사와 현실의 타당성을
  별도로 기록한다. 완료 근거: 외부 검증 결과, 성능/불확실성, 공개 가능한 활동·장소·조건.
- [x] **A1-8. 사용자 선택·조건 상세·보류 사유 화면 연결 — 구현·격리 브라우저 검증 완료.**
  첫 지점 고정 조회에서 사용자 지점·활동·기간 선택으로 연결한다. 점수 공개 조건이
  충족되기 전에도 입력·출처·지원·제한·보류 사유를 볼 수 있게 한다.
  완료 근거: 같은 선택 조건으로 API와 화면이 일치하며 null이 0점/안전으로 바뀌지 않는 화면 확인.

- [x] **A1 후속 조건 계산.** 사용자가 설정한 범위·중요도에 대한 종합 조건 일치 산술을 별도 API와 프론트로 구현하고 전6활동을 시험했다. 이 완료 항목을 A1-5~7의 과학적 수치 환경 모델·외부 검증 완료로 대체하지 않는다.

A1-3과 A1-4는 병행할 수 있다. A1-8의 상태·근거 표시는 수치 검증이 끝나기 전에도 진행할 수 있다.
첫 검증을 좁히는 것은 A1 전체의 나머지 활동을 완료 처리하거나 요구사항에서 삭제한다는 뜻이 아니다.
