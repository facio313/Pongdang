# Pongdang API 인증·데이터 호출 점검

검사 시각: 2026-09-13T23:11:34.771843+09:00 ~ 2026-09-13T23:20:05.957156+09:00

사용자가 로컬 엑셀에 입력한 인증값으로 공식 API를 직접 조회했다. 키는 실행 프로세스 메모리에서만 읽고 보고서·명령줄·소스에 기록하지 않았다. 각 조회는 작은 표본으로 제한했다.

이 결과는 현재 맥에서의 인증·자료 수신 검사다. 운영 서버의 출발지 IP, 브라우저 지도 렌더링, Pongdang DB 적재·자동 수집은 검사 범위가 아니다. 앱에 API 어댑터나 스케줄러를 추가하지 않았다.

## 지금 해야 할 일

1. **카카오맵 활성화:** Pongdang 앱의 카카오맵 → 사용 설정 → 상태를 ON으로 설정한다. REST 장소검색·주소검색과 JavaScript SDK 모두 `OPEN_MAP_AND_LOCAL service disabled` 응답이었다. 현재 공식 정책상 개발자 계정에서 첫 번째 활성화 앱만 무료 쿼터를 받으므로 앱의 무료 쿼터 표시도 확인한다. [공식 사용 방법](https://developers.kakao.com/docs/ko/kakaomap/common)
2. **기상청 API허브 AWS 매분자료 활용신청:** 서버 응답이 신청 필요를 직접 명시했다. 같은 API허브 키의 해양기상부이 호출은 성공했다. [AWS 매분자료 신청](https://apihub.kma.go.kr/apiList.do?seqApi=2&seqApiSub=239)
3. **아래 인증 거절 서비스의 활용신청 상태 확인:** 공공데이터포털 키로 여러 서비스가 성공했다. 코드 30은 전체 키가 틀렸다는 결론이 아니라 해당 서비스의 신청·승인·키 연결 상태 확인 대상이다. 미신청이면 신청하고, 이미 신청했다면 승인·중지·이용기간·반영 여부를 확인한다. [공공데이터포털 오류코드 안내](https://www.data.go.kr/tcs/dss/selectErrCodePopupView.do)

## 연결 구현 시 반영할 점

- 생활기상지수 신청 페이지 제목은 4.0이지만 현재 공식 명세의 UV 경로는 `LivingWthrIdxServiceV5/getUVIdxV5`이며 이 경로로 성공했다.
- 키를 발급받는 것과 각 API의 활용신청 승인은 별개다. 수질·대기·관광·해양의 서비스별 승인 상태를 따로 관리한다.
- 국문 TourAPI 호출은 성공했다. 운영계정 신청 시 심의승인 대상이며, 이번 응답만으로 현재 계정 등급을 확인한 것은 아니다. K-water 방류정보는 개발·운영 모두 심의승인으로 안내된다.
- NIER 수질 DB는 `getWaterMeasuringList.header`와 `getWaterMeasuringList.item` 구조를 사용한다. TourAPI 지역별 방문자수는 해수욕장 실시간 혼잡도 자료가 아니다.
- 장소 코드·관측소 ID·날짜와 시각·측정 단위·결측값을 제공기관 의미대로 보존해야 한다. 이번 표본 수신을 앱의 안전점수나 실시간 안전 판정으로 사용하지 않았다.
- 실제 키가 든 엑셀은 로컬 docs에 보존하고 Git 추적에서 제외했다. 이 보고서와 JSON에는 인증값이 없다.
