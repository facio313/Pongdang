# 계곡·호수·저수지 자료 연결 — 2026-09-30

목표는 기존 실제 수집 자료로 내륙 명소의 분류·상세·기상/담수 근거를 연결하고, 해양 파고나 가까운 바다 수온을 내륙 점수에 섞지 않는 것이다. CSS, 운영 DB, API 키, 수집 설정, 배포는 변경하지 않았다. 기존 사용자 수정은 보존했다. 이 문서는 내륙 작업만 기록하며 전체 작업 상태는 `CURRENT.md`에서 관리한다.

## 구현된 계약

- `place_kinds.py`에 beach/valley/lake/reservoir를 정의했다. `livecams/places.water_place_kind_sql(alias)`가 저장된 종류, 공급자 분류, TourAPI 자연관광(category 12)의 명확한 호수/저수지 이름과 저장된 공식 cat3=A01011700을 함께 읽는다. 단순히 이름이 “호”로 끝난다는 이유로 호수로 추정하지 않는다. 이 공통 SQL을 명소 목록과 여행 후보 조회가 재사용한다(여행 후보 통합은 부모 작업).
- TourAPI 정상 재수집 때 공식 cat3를 lake/reservoir로 정규화한다. 기존 저장 함수는 공급자 수정시각이 같아도 같은 provider/source_id의 장소 종류를 갱신하며 장소 ID를 유지한다. 이 재수집 경로를 폐기 가능한 DB에서 검증했다. 새 공급자·스키마·수집 실행은 추가하지 않았다.
- 내륙에도 기존 장소 동일성 처리, 사진 수집 대상, TourAPI 상세 직접/간접 연결을 적용했다. 상세가 없으면 pending/미수집으로 남는다.
- 내륙 조건 생성은 KMA 기상과 NIER/HRFCO 담수 자료를 사용한다. 해양 공급자·파고는 내륙 조건에서 제외한다. 명시적 잘못된 해양 연결도 점수에 쓰지 않는다. 해양 활동인 surf/mudflat은 내륙 후보에서 제외한다.
- 내륙 수영은 수온·기온·바람·강수를 보고 수위·유량은 원자료로 보존한다. 수위·유량 점수 곡선은 아직 미설정이다. 가까운 관측소라는 이유만으로 같은 수역이라고 간주하지 않으며, 담수 수온/수위/유량의 점수 사용에는 검토된 대표 관측소 연결이 필요하다. 수영 추천에는 별도의 활동 지원 근거가 필요하다. 안전 상태는 unknown을 유지한다.
- 모든 내륙 활동의 상세 근거에 담수 수온/수위/유량을 요청해, 휴식이 선택돼도 저장 관측값을 읽을 수 있다. 관측소·관측시각·단위·과거자료 여부를 표시한다. NIER 검사자료에는 해양 WQI 등급을 적용하지 않고 `inland-sampling.v1`, grade=null로 반환한다. 원자료 단위가 없으면 추정하지 않는다.
- 조건 envelope의 `place_kind`를 worker의 압축 저장/재구성에도 보존했다. 점수·추천·저장 모델은 1.1.0으로 갱신했다. 새 코드 실행 후 worker가 1.1.0 결과를 게시하기 전에는 이전 1.0.0 결과가 조회되지 않으므로 해변을 포함한 점수가 일시적으로 대기 상태일 수 있다. 브라우저가 새 모델의 대기 응답 위에 이전 모델 점수를 보존하지 못하도록 회귀 검증을 추가했다.
- UI 분류/필터/라벨은 네 종류를 지원한다. 호수/저수지의 대표 사진이 없으면 미제공 상태를 보이고 해변 예시 사진으로 바꾸지 않는다. 점수 설명도 바다/담수 조건을 구분한다. CSS 수정은 없다.

## 실제 저장 자료 읽기 확인과 UI 검증의 구분

실행 중인 `localhost:8000`의 알려진 GET 읽기 API만 사용했다. 서버 재시작, 수집 실행, 기존 DB 쓰기를 하지 않았다. 현재 프로세스는 이전 코드여서 `kind=lake`와 `kind=reservoir` 요청은 여전히 422이고 beach/valley만 허용한다. 아래 자료의 존재가 새 코드의 운영 적용 완료를 뜻하지 않는다.

- 강원도 valley 목록: 58곳. 전체 spots 원자료: 7,913건.
- `datasets/spots`의 저수지 이름 검색으로 저장된 TourAPI 한국어 장소 7개를 확인했다: 경포저수지(7775), 사기막저수지(7721), 토교저수지(철새도래지)(4926), 학저수지(4896), 잠곡저수지(4894), 용화저수지(4893), 건등저수지(2416). 공통 조회 분류는 새 코드 실행 시 이런 기존 일반 관광 타입도 재사용한다.
- 영랑호(3320), 경포호(철새도래지)(7760), 소양호(춘천)(2360), 소양호(양구)(5140), 소양호(인제)(5274) 저장 이름을 확인했다. 이름 검색은 주소 등도 검색하므로 결과 수를 분류 개수로 해석하지 않았다.
- 선택한 실제 명소의 `place-details` 응답은 pending, fetched_at 없음이었다. 영랑호·경포호처럼 명확한 호수 suffix가 없는 장소는 다음 정상 catalog 재수집에서 공식 cat3가 정규화되거나 공식 상세 분류가 저장되어야 호수로 분류된다.
- NIER source의 station spot 6곳(경포호1/2, 향호, 강릉, 쌍촌, 포남), HRFCO source의 station spot 6곳을 확인했다. snapshot 조회 수는 각각 6건/150건이었다. NIER 표본은 2026-07-06 관측, 9월 14일 수집, 7월 7일 만료된 과거 검사자료였다. HRFCO 표본은 9월 30일 04:50 KST 관측, 05:01:51 수집, 05:20 만료였다. 이 표본으로 전체 자료가 현재 유효하다고 판단하지 않았다.

UI 확인은 별도 Vite 포트 5188에서 모든 `/api/**` 요청을 가로채는 OFFLINE TEST 계약 응답으로 수행했다. 실제 수집값처럼 DB에 저장하지 않았다. 모바일 390px과 데스크톱 1440px에서 호수/저수지 선택, 미수집 상세, 담수 관측소 이름·수위·시각·같은 수역 미확인 표시, 사진 없음, 가로 넘침 없음(실제 DOM 확인)을 검증했다. 지도 외부 연결은 이 격리 화면에서 미설정/실패 상태이며 지도 provider 연동을 검증했다고 주장하지 않는다. 검사 증거는 `output/playwright/inland-ui.js`, `inland-mobile.png`, `inland-desktop.png`이고 스크린샷을 직접 확인했다.

## 남은 실행/자료 제한

1. 새 코드가 기존 실행 서버에 아직 적용되지 않았다. 배포·재시작·worker 정상 재수집/새 모델 게시 후 실제 화면 결과는 별도 실행 단계에서 확인해야 한다.
2. 같은 수역의 대표 관측소 검토, 공식 수영 지원·통제, 상류 강우·방류 연결은 미확인이다. 없는 수치·안전점수·허가를 생성하지 않았다.
3. 추가 저수지 공급자와 신규 분류 체계는 공식 응답 계약 및 승인 범위 확인 후에만 연결한다. 이번에는 새 키 요청이나 활성화가 없다.
4. 작업 전용 Playwright 세션, Vite5188, PostgreSQL55437을 종료했다. 작업 전용 PG 데이터 디렉터리는 삭제하고 `/tmp/pongdang-inland-pg.dGFceQ/server.log`는 보존했다. 기존 실행 서버는 유지했다.
5. 일반 사용자 지정 범위 비교 API의 기존 활동 allowlist는 유지했다. 이번 내륙 장소별 조건 프로필은 게시 점수/상세 근거 경로에 적용된다.
