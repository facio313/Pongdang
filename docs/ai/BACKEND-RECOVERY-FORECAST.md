# 예보 투영·수온 조회 복구 · 2026-09-21

- 요청 범위: 프런트 수정 없이 운영 가능한 백엔드 조회·수집 복구. 이 작업은 `forecast/storage.py`, `twin/api.py`와 관련 테스트만 담당한다. 조건 점수·상세 수집 변경은 다른 작업자가 담당한다.
- 예보 원인: 과거 31일을 포함하는 원자료에서 5,000개 상한을 먼저 적용하여, 동일 예보 대상의 발행 이력과 만료 자료만으로 `SOURCE_SCOPE_TOO_LARGE`가 발생했다.
- 예보 수정: 기존 Python의 자연 예보 대상 식별 방식과 최신 수정 선택을 SQL의 상한 앞에 적용한다. 정상 작업은 현재 유효한 예보 대상만 투영하며, 기존 저장 예보와 원자료 이력은 삭제하지 않는다. 최신 결측 수정도 그대로 선택한다. 조석 v2의 만료 슬롯은 이전 식별자를 억제하는 근거로 유지하고, 억제 대상도 상한 전에 제외한다. 실제 최신 유효 대상이 상한을 넘으면 기존의 원자적 실패를 유지한다.
- 수온 원인: 수온 관측만 읽는 화면도 같은 요청에서 평가·예보를 필수 조회했다. 기존 진단에서 수온 조회 약 0.03초에 비해 예보 SELECT 두 개가 각각 1~1.36초였고, 동시 화면 요청에서는 503이 재현됐다.
- 수온 수정: `/water-temperature`는 수온과 관측소 연결만 읽는다. 응답 필드 구조는 유지하며 생략한 평가·예보는 `not_requested`, 평가 사유는 `temperature_only_view`로 명시한다. 자료가 없다고 대신 주장하거나 점수·안전·수온 값을 만들지 않는다. `/water-twin`의 전체 파생 레이어 조회는 유지한다.
- 자동 검증: 전용 폐기 DB `127.0.0.1:32770/pongdang_test`에서 예보 범위·공간·feature·평가/예보/조석 72개 테스트 통과(75.93초). 최신 발행 결측 5,002행, 만료 이력 5,002행, 실제 유효 자료의 상한 초과 실패, 기존 이력 보존·멱등성, 수온의 파생 조회 독립성을 포함한다. 변경 4개 Python 파일 Ruff check/format 통과. 기존 라이브러리 deprecation 경고 2개.
- 실제 규모 검증: 운영 자료를 복제한 폐기 DB `127.0.0.1:32768/pongdang_test`에서 현재·최신 예보 2,384행 선택에 0.819초. 예보 투영은 첫 실행 2,184행 추가/13.085초, 재실행 0행/4.275초로 성공했다. 이 쓰기는 복제 DB에만 수행했다.
- 수온 실측: 같은 복제 DB의 실제 앱 HTTP 조회에서 기존 503 대상 5476/2915/472/5608과 실제 수온 관측 지점 13 모두 200, 단건 0.070~0.114초. 12개 동시 요청도 모두 200(0.121~0.901초). 수온 연결이 없는 네 장소는 빈 layers를 유지하고 관측 지점 13은 실제 1개 층을 반환했다.
- 상태: 담당 구현·검증 완료. 커밋·푸시·운영 DB 변경·배포는 실행하지 않았다. 전체 복구 통합 및 최종 운영 반영은 상위 작업에서 이어간다.
