# 추천 자료와 AI 연결 · 2026-09-30

## 현재 확인과 구현

추천 후보 API `/api/data/travel/recommendations`는 원래부터 취향/분류/공식제한 규칙이며 모델 호출이 아니다. AI 대화가 이 도구를 호출할 때에도 후보 순위는 서버 규칙이 정한다. 기본값과 루트·backend 로컬 환경의 선택 모델은 `gpt-5.6-luna`, 코드의 호출 경로는 `POST https://api.openai.com/v1/responses`다. 두 환경에 키가 존재하지만 API 권한/잔여 예산/실제 모델 성공 여부를 증명하지 않으며 이번에 유료 호출은 하지 않았다. 키값은 출력하거나 기록하지 않았다.

새 `published-evidence.v3`는 명시 조건/제외/공식 제한 이후 최대30곳을 고르고 `read_condition_set`으로 완성된 저장 조건 결과를 한 SELECT로 조회한다. 기본 관측+현재시각 예보 fallback은 최대60행이며, 선택 환경지표가 다른 활동 결과에 들어 있을 때는 같은 검토 mapping_id의 근거만 추가로 읽는다(최대180행). 자료가 없으면 원시 재계산·외부제공처 호출·DB쓰기를 하지 않는다. 필수 장소, 취향과 명시 환경일치, 완전한 동일항목 조건 참고점수, 기존 목록순으로 정렬한다. 항목이 다른 점수·부분점수·보존된 이전 자료를 같은 총점으로 비교하지 않는다. 공식 제한과 활동 미지원은 우선 제외한다. 참고점수는 안전 판정이 아니다.

Luna가 호출하는 여행 도구에는 이 비교점수·조회 모드·저장 결과 generation 근거를 제공한다. 직접 후보 API에는 모델을 사용하지 않았다는 정보를 남긴다. 설명용 Responses API에도 `reasoning.effort=none`을 명시해 기본 추론량의 불필요한 비용/지연을 피한다. 기존 AI 대화는 이미 같은 설정이었다.

장소 목록과 여행 후보 검색은 `water_place_kind_sql`의 같은 분류 기준을 사용한다. 기존 저장 `type=place`인 관광지라도 공식 관광 분류와 저수지 이름으로 확인되면 두 경로에서 동일한 저수지로 제공한다. 기본 여행 역할 필터가 원래 type만 보아 후보에서 누락시키던 문제도 함께 수정했다. 출발 시각·사용자 취향에 따른 추천 결과 자체를 전 사용자 공통 캐시에 저장하지는 않는다.

## 공식 문서 확인

- [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna): Responses·구조화 출력 지원.
- [추론 설정](https://developers.openai.com/api/docs/guides/reasoning): GPT-5.6의 기본 effort는 medium, none/low 선택 가능. 실제 지연 향상은 이 프로젝트에서 유료 모델 호출로 측정하지 않았다.
- [TypeSafe HTTP API](https://docs.typesafe.ai/api): Jev는 `POST https://api.typesafe.ai/v1/systemone`에서 state와 typed questions를 받아 Choice/Score/Noul을 반환한다. OpenAI Responses와 별도 서비스다.
- [TypeSafe 재순위 예제](https://docs.typesafe.ai/cookbooks/rerank_typesafe): 먼저 후보를 좁히고 의미 비교를 적용하는 패턴. 예제의 평가결과를 Pongdang의 성능으로 인용하지 않는다.

최초 조사에서는 사용자가 말한 Decision API의 정확한 계약을 확인하지 못해 질문했다. 2026-09-30 후속 요청에서 사용자가 OpenAI DevDay 발표를 뜻한다고 설명하고, 해당 API는 이번 작업에서 제외하도록 지시했다. 이 요청에 따라 Decision API 추가 조사·연동은 제외하고 기존 Responses 개선을 유지한다. 이번 후속 턴에서는 발표 내용이나 공개 상태를 새로 검증했다고 주장하지 않는다.

## Jev 적용안

첫 적용 후보는 명소 소개와 확인된 취향의 의미 일치다. 장소의 저장된 소개·분류·시설정보와 사용자가 선택한 조건을 입력으로 주고, 혼잡/안전/입수 가능성은 추정 대상에서 제외한다. Choice는 장소 유형 또는 요청 의도 선택, Score는 '소개 문구가 취향을 얼마나 직접 뒷받침하는가', Noul은 특정 문장을 실제 출처가 지지하는지를 확인하는 데 쓸 수 있다.

추천 우선순위는 (1) 자유문장 취향을 기존 선택지로 해석해 사용자에게 확인, (2) 이미 추린 후보의 소개/시설 의미 비교, (3) Luna 설명의 출처 일치 검사다. 수온·파고·거리·수위 계산, 공식 통제 해제, 안전점수 생성에는 쓰지 않는다. 독립된 여러 의미 질문은 한 요청으로 묶고 입력자료 revision+질문 version으로 재사용한다. 별도 TypeSafe 키·요금·계정 접근 및 한국어 명소 샘플 평가가 확인되기 전에는 운영 순위에 자동 적용하지 않는다. 이번 목표 6은 활용 아이디어 검토이므로 새 의존성과 유료 호출은 추가하지 않았다.

## 검증 상태

- 지정 Ruff/format 및 root 단위·통합 관련118개 통과. 이후 공통 수역 분류를 후보 검색에 적용한 변경은 여행 통합47개로 재검증해 모두 통과했다. 두 실행에는 같은 테스트가 일부 포함되므로 숫자를 합산하지 않는다.
- 저장 조건 조회는 추천 요청당 한 번이며 요청 안에서 원시 조건 계산·경로 API를 호출하지 않는 회귀 검증을 통과했다. 최대30 후보, 예보 범위 밖 상태, 필수 장소, 결측·부분·이전 점수, 공식 제한, 이동수단 대화 변경도 확인했다.
- loopback55483의 이번 작업 전용 PostgreSQL18 `pongdang_test`에서 실행했다. 검증 후 서버를 종료하고 해당 임시 데이터 디렉터리를 삭제했다. 기존 개발 서버·DB는 수정하지 않았다.
- 모의 브라우저에서 새 조건 참고점수 근거가 데스크톱·모바일 추천 후보에 표시됨을 이동수단 담당 작업에서 확인했다. 모델/공급자 실호출의 응답시간은 측정하지 않았다.
- 검증 로그: `.local/recommend-evidence-20260930/`.
- CSS 변경 없음. 기존 상세화면/CSS 변경은 이번 변경과 별개로 보존했다.
- Decision API 제외 후 현재 구현과 관련 테스트의 범위를 요청 항목에 대조해 나머지 로컬 개발 범위를 완료로 확인했다. 후속 턴에서 동작 코드는 변경하지 않았으므로 같은 검사는 재실행하지 않았다. 실제 공급자 계정 권한·배포·유료 응답시간 측정은 위 검증 결과에 포함하지 않는다.
