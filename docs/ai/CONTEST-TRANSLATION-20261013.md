# 저장형 공공 장소 자동번역 — 2026-10-13

## 목표와 경계

사용자가 확정한 “앱 안에서 자동번역하고 결과 보관”을 구현했다. 기존
`app.ai.provider.ResponsesProvider`, 설정된 모델, 전역 AI 비용·호출·동시성 제한을
재사용한다. 새 제공자·의존성·서비스는 추가하지 않았다. 이번 작업은 로컬 코드와
폐기 가능한 PostgreSQL 18 검증까지이며 실제 유료 모델 호출·운영 데이터 변경·
배포는 하지 않았다.

공식 외국어 자료를 우선하고, 한국어로 대체 표시하는 경로에만 저장된 자동번역을
사용한다. 원문 제공자의 검증 표시와 번역 상태는 별개다. 자동번역의 지명·번역 품질을
검증된 공식 외국어 정보로 표시하지 않는다.

## 구현

- `backend/app/place_translations/service.py`: `TOURAPI_KOREAN`과 `KAKAO_LOCAL`의
  공개 명칭·주소 및 해당 TourAPI 원천에 연결된 공개 소개만 번역한다. 연락처·사용자
  정보·원시 응답·운영시간·안전 판단은 보내지 않는다. 영어 `en`, 일본어 `ja`, 중국어
  간체 `zh-CN`을 지원한다. 번체 `zh-TW`에는 기존 원문 대체 표시가 적용된다.
- 대상 원문은 명칭 300자, 주소 1,000자, 소개 2,000자 이하로 제한한다. 긴 자료는
  임의로 자르지 않고 번역 대상에서 제외한다. 요청 전체의 기존 AI 입력 상한도
  적용한다. 원문 수집을 추가로 호출하지 않고 이미 저장된 자료만 사용한다.
- `collector.py`: 사용자 후속 요청에 따라 기존 수집 worker의 마지막 작업으로
  하루 한 번 실행한다. 작업 종료 후 24시간을 기다리며 실패·예산 소진 시에도
  더 일찍 자동 재시도하지 않는다. 예산 갱신 시각에 맞춘 조기 재실행은 제거했다.
  기본값은 활성화이며 기존 AI 제공자·키·가격 설정 및 예산이 허용할 때만 호출한다.
  기본 배치는 한 언어 한 건, 최대 설정값은 세 건이다. 하루 기본 3회, 60,000
  microUSD(0.06 USD)의 별도 보수적 예약 한도를 적용한다. 이 비용은 기존 전역 AI
  한도 안에 포함되며 추가 예산이 아니다. 한 장소의 세 언어가 각각 한 호출이므로
  전체 목록이 즉시 번역되는 구조는 아니다.
- 전역 AI admission lease와 일일 호출·토큰·비용 예약을 공유한다. 실패 시에도
  보수적 예약을 환급하지 않는다. 한 번의 모델 호출은 HTTP 제한과 요청 전체 제한
  중 짧은 값을 사용하고, 배치의 모델 작업은 최대 30초로 제한한다. 예약·준비에 쓴
  시간도 모델 deadline에서 차감하여 느린 응답이 lease보다 오래 지속되지 않게
  했다. 종료 시 lease를 해제한다.
- 응답은 기존 Responses API의 엄격한 JSON 구조로 제한하고 필수 세 필드만
  수용한다. 원문의 빈 값·누락, 숫자와 URL 보존 여부를 추가 검사한다. 프롬프트에
  사실 추가·요약·교정 금지, 불확실한 지명은 한국어 보존을 명시했다. 이런 검사는
  번역 품질 자체를 인증하지 않는다.
- `migrations.py`와 `app.schema`: 명시적 추가형 schema 22 migration에 번역 결과와
  번역 일일 예산 테이블을 추가한다. 기존 collection 및 전역 AI 예산은 보존한다.
  앱 시작과 GET 요청에서 migration이나 seed를 실행하지 않는다.
- 저장 키는 제공자, 제공자 원천 ID, 공개 원문 SHA-256 해시, 언어, 프롬프트와 모델
  버전이다. 읽을 때 현재 원문과 해시가 모두 일치해야 한다. 원문 변경 즉시 과거
  번역은 표시하지 않으며 worker가 새 버전을 처리한다. 모델 응답 중 원문이 바뀌어도
  해당 결과를 게시하지 않는다. 실패는 원문으로 돌아가고 기존 worker와 레코드별
  지수 backoff를 사용한다.
- `read_place_translations(connection, spot_ids, locale)`는 한 번에 최대 100개 장소의
  현재 저장 번역만 반환하는 읽기 전용 함수다. 테이블이 아직 없거나 번역이 없으면
  빈 결과를 반환한다. GET 경로에는 모델 호출과 쓰기가 없다.
- `config.py`, `ingestion/worker.py`, `compose.yaml`은 위 설정·작업 등록과 collector의
  기존 AI 환경변수 전달만 추가했다. collector로 전달하는 공유 AI 설정 16개의
  기본값은 backend와 같다. SSO 인증 정보는 추가로 전달하지 않는다.

저장 번역 소비는 병렬 작업의 `travel/catalog.py`, `place_details/api.py`에서 연결했다.
추천 목록과 상세의 소비자는 원천 제공자·ID를 다시 확인하며, 목록은 원문 명칭·주소도
확인한다. 반환 metadata에는 `translation_status=machine_translated`, 원문 언어,
원문 명칭·주소, 모델·버전·번역 시각이 있다. 프런트 표시와 소비 통합 검증은
`docs/ai/CONTEST-CATALOG-20261013.md` 및 상위 작업 기록을 따른다.

## 실제 검증

전용 임시 PostgreSQL 18, loopback 52531의 `pongdang_test`만 사용했다. API 키는
테스트 문자열이며 Responses HTTP는 `httpx.MockTransport`, timeout 검사는 취소 가능한
지연 stub으로 대체했다. `ops/verify_local.py`에 변경 파일과 관련 테스트를 명시했다.

- 저장 번역 관련 테스트 18개 통과: 3개 언어, 원문 변경·호출 중 변경, 읽기 전용 조회,
  실패·backoff, 로컬 및 전역 호출·금액 한도, 비활성·키 미설정, 구조·숫자·빈 값 보존,
  응답 거부·잘못된 JSON, 명시적 schema 21→22 보존, 두 종류의 전체 timeout과 lease
  해제를 포함한다.
- 기존 AI 예산 테스트 11개 통과. 예산 구현 자체는 변경하지 않았다.
- schema 호환성 테스트 5개 통과. 최초 실행에서 기존 schema 20은 migration하지
  않는다는 기대와 21을 미지원으로 보는 기대가 현행 21 동작과도 어긋나 2개가
  실패했다. 현재 버전의 무변경 재시작과 알 수 없는 다음 버전 거부로 기대를 바로잡고,
  실제 21→22 데이터 보존은 새 DB 테스트로 확인했다.
- 수정 Python 파일의 Ruff 및 포맷 검사, 변경 whitespace 검사 통과.
- Docker CLI와 PyYAML은 없어 해당 도구의 Compose 파서 검증은 실행하지 않았다.
  표준 라이브러리 텍스트 검사로 AI 설정 16개 동일성과 번역 기본값 4개를 확인했다.
  상위 작업은 변경한 collector 환경변수 20개 블록을 Ruby YAML 파서로 읽는 검사를
  통과했다. 구버전 Ruby YAML 1.1 파서는 변경하지 않은 기존 flow scalar에서 전체
  파일 읽기가 실패해 전체 Compose 검증 근거로 사용하지 않았다. 컨테이너는 시작하지
  않았다.

전체 목록의 번역 품질과 실제 모델 응답은 이번 검증 대상이 아니며, 실데이터가 없을
때는 한국어 원문이 유지되는 것이 의도한 동작이다.

## 최종 정리

- 로컬 코드 구현 및 관련 검증 완료. 커밋·푸시·배포 없음.
- 번역 전용 임시 PostgreSQL은 `pg_ctl -w stop` 성공 후 자신의 임시 디렉터리와 함께
  삭제했다. 다른 작업의 DB와 운영 DB에는 연결하지 않았다.
