# 공모전 후속 추천 논리 수정 · 2026-10-13

## 요청과 제약

- 공모전 감사 후 사용자 승인 범위: 물 활동(수영·서핑) 40점 이상 우선 정책 유지, 개장 시즌정보를 순위에서 제외하고 안내로만 표시, 오늘/여행 추천의 적격성 일치, 기상청 격자 자료의 기상 선호 비교 연결.
- 운영 영향 최소: 점수 곡선·집계·저장 모델 1.3.0·DB 스키마·원천 수집을 변경하지 않는다. 추천 선택 규칙만 1.4.0으로 분리했다.
- DB 및 원천 API는 읽기 전용 제품 경로. 유료 모델/공급자 호출, 운영 연결, 커밋·푸시·배포를 실행하지 않았다.
- 다른 병렬 작업은 별도 담당자가 수행했다. 이 기록은 추천 논리 소유 범위만 설명한다.

## 구현

- `backend/app/water_index/recommendation.py`: 순수 `activity_eligibility`를 추출하여 필수 지표·공식 통제·활동 미지원·내륙 수영 근거·18°C 미만·물때 규칙을 공통 적용한다. 그 다음 물때 후순위 → 40점 이상 수영/서핑 우선 → 점수 순으로 선택한다. 점수는 재계산하지 않는다.
- 개장기간 밖/미확인은 `needs_confirmation`과 기존 사유로 표시한다. 이 값은 순위·점수·대안 종류를 바꾸지 않는다. `recommendation_api.py`는 확인된 해변의 개장 정보 조회 실패도 `unconfirmed`로 표시하고 실패 사유를 보존한다.
- `backend/app/travel/published.py`: 한 번에 읽은 저장 점수에 같은 적격성을 붙인다. 입수 후보인 해변 수영/서핑에만 기존 조석 읽기를 전체 최대 5초/개별 최대 2초 예산으로 재사용한다. 새 공급자 요청·점수 계산·DB 쓰기는 없다. 물때 조회 실패는 명시하고 유리한 물때로 바꾸지 않는다.
- `backend/app/travel/recommend.py`: 저수온·공식 통제·미지원·내륙 수영 미확인은 제외한다. 필수 자료 부족은 기존 장소 탐색을 남기되 활동 적격성과 점수 비교 보류를 명시한다. 물때 후순위는 여행 후보 정렬에도 적용한다.
- `backend/app/travel/environment.py`: 대표관측 자료를 보존하고 없는 기상 항목만 기상청 `containing_forecast_grid`에서 비교한다. 출처·공간범위·시각·원문 상태를 보존하며 기존 점수의 입력 검증을 재사용한다. 결측·만료·상충·이전 자료·일반 주변 관측소를 유리한 값으로 보완하지 않는다.
- 미래 여행 추천의 저장 결과 조회는 explicit `as_of`가 최신 예보를 과거 아카이브 계약으로 오인하게 하던 부분만 수정했다. 미래에는 `as_of`를 생략하고 `now`로 현재 조회 기준을 유지한다. 관측으로 대체하지 않는다.
- 다른 담당자가 추가한 `VISIT_TIME_WINDOWS`를 `preview_time`에서 사용해 오전09/오후13/저녁18 방문 미리보기를 구분한다. 사용자 출발 시각을 덮어쓰지 않는다.

## 프런트 계약

- `model_version=1.4.0`은 추천 규칙 버전이며 활동 조건 점수 모델은 1.3.0이다.
- `water_activity_preferred`: `activity`는 선택된 수영/서핑, `rival`은 더 높은 비교 활동, `value`는 선택 점수, `threshold=40.0`. 입수 가능/안전을 확인했다는 의미가 아니다.
- `beach_closed_season_product_rule`, `beach_season_unconfirmed`: 안내 전용. 시즌만으로 `demoted`가 되지 않으며 `needs_confirmation`은 표시용이다.
- 여행 추천 `conditions`에 `activity_eligibility`, `eligibility_reasons`, `tide`를 추가했다. 원본 `published_condition`에도 같은 정보가 있으며 `tide_lookup_status`는 available/no_data/unavailable을 구분한다.
- 제외 목록은 기존 official_restriction/selected_activity_unsupported 외에 `selected_activity_ineligible`과 `rules_applied`로 저수온/내륙 수영 근거 미확인을 설명한다.
- 기상 선호 결과 `criteria[].evidence[]`에 `relation`, `spatial_scope`를 추가했으며 `mapping_id=null`인 기상 격자를 대표관측소로 가장하지 않는다.

## 실제 검증

- 직접 생성한 임시 PostgreSQL18 클러스터의 loopback `pongdang_test`만 사용했다. 테스트 환경변수에 이 클러스터를 명시했고, 추천 통합 fixture는 `_env_file=None`으로 운영 환경파일을 읽지 않게 했다.
- `ops/verify_local.py`에 소유 변경파일과 관련 테스트를 명시하여 Ruff lint/format 통과.
- 관련 단위·통합 162개 고유 사례 통과 범위: 추천34, 추천 통합11, 추천 복원성14, 신규 여행 적격성18, 저장결과14, 여행 키워드/경로29, 여행 규칙29, 복수방문13.
- 최초158개 실행에서 기존의 휴식우선/대안 기대값과 불완전한 점수 fixture로 3개 실패했다. 승인된 정책에 맞춰 기대값을 수정하고 실제 필수 지표를 fixture에 채웠다. 관련 재검증에서 대안 기대값1개를 추가로 수정했다. 최종 추천 관련89개와 추가된 DB 통합을 포함한11개 재검증이 통과했다. 이미 통과한 나머지71개는 해당 코드가 바뀌지 않아 반복하지 않았다.
- DB 통합은 실제 저장 자료로 수온17°C의 높은 점수를 오늘/여행 양쪽에서 추천 제외하는 것, 같은 조석이 두 경로에서 같은 물때 후순위를 만드는 것을 확인했다.
- 새 단위 검증은 39.9/40.0 경계, 시즌 조회 실패와 미확인의 동일 선택, 격자 출처/공간범위 보존, 격자 선호 비교100점, 결측·상충·이전자료 보존, 미래 저장조회 계약, 방문 시간대를 확인했다.
- 기존 Starlette/httpx/AnyIO 폐기예정 경고2개가 있으며 기능 실패는 없다. 전체 빌드·브라우저·운영 배포 검증은 실행하지 않았다.
- 소유 파일 `git diff --check` 통과. 소유 임시 DB를 정상 종료하고 클러스터·설정·로그를 제거했다.

## 남은 통합

- root 담당 프런트에서 시즌 안내 전용 정책, 물 활동 우선의 비안전 설명, 여행 적격성 사유를 표시한다.
- 관광 카탈로그·경로/시간대 담당자의 별도 변경과 최종 통합은 root가 확인한다.
- 실제 운영 버전과 로컬 소스가 달랐던 감사 관찰은 원인 미확인 상태다. 이번 변경을 운영에 반영하거나 운영이 변경되었다고 주장하지 않는다.
