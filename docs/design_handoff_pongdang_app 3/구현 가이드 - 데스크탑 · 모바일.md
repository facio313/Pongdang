## 1. 반응형 전략 — 이게 첫 번째 결정입니다

데스크탑은 모바일을 넓힌 것이 **아닙니다.** 문법이 다릅니다.

| | 모바일 390 | 데스크탑 1440 |
| --- | --- | --- |
| 면 | 흰 카드 + radius 18 + 그림자 | **카드 없음 · 그림자 없음.** 괘선(1px)과 여백으로만 구분 |
| 섹션 | 세로 카드 스택 | **200px 라벨 열 + 1fr 본문**의 2열 그리드, 행마다 하단 괘선 |
| 히어로 | 코발트 그라디언트 라운드 하단 | 같은 코발트 + **물결 SVG 경계**로 흰 본문에 이어짐 |
| 네비 | 하단 탭바 6칸 | **상단 인라인 네비** (PONGDANG + 6항목) |
| 마스코트 | 작은 표지(20~66px) | 히어로 186~250px, 항목 표지 34~78px |

그래서 **미디어 쿼리만으로 재사용하지 마세요.** 권장 구조:

```
frontend/src/
  pages/SpotsPage.tsx          ← 라우트 진입점. 데이터 훅 + 분기만
  pages/spots/SpotsMobile.tsx  ← 390 레이아웃
  pages/spots/SpotsDesktop.tsx ← 1440 레이아웃
  pages/spots/spotsPage.css    ← .pd-spots 루트에 스코프, 안에서 @media로 분리
  hooks/useIsDesktop.ts        ← matchMedia('(min-width:1080px)') + resize 구독
```

- **분기 기준 1080px.** 1080 미만은 모바일 레이아웃을 그대로 늘려 쓰고(최대 폭 520px 가운데 정렬), 1080 이상은 데스크탑. 1440은 디자인 기준 폭이며 그 이상에서는 좌우 56px 여백을 유지한 채 본문이 늘어납니다 (컨테이너 `max-width:1600px;margin:0 auto`).
- **공유해야 하는 것**: 데이터 훅(`useResource`), `groupAGrade.ts`(등급·색·NULL), `mapLocations.ts`(좌표), 코스/취향 상태, 문구 상수. 두 레이아웃이 같은 props를 받게 하고 **문구를 두 벌 쓰지 마세요.**
- **공유하지 않는 것**: 마크업과 CSS. 억지로 한 컴포넌트에 `isDesktop` 삼항을 20개 박으면 유지가 안 됩니다.
- SSR 없음 → `useIsDesktop`은 첫 렌더에서 `window.matchMedia` 동기 평가로 시작해도 됩니다.
